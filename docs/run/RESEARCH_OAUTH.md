# Research: Can end users sign in with their existing Claude / ChatGPT / Manus subscription to power Euangelion's LLM features?

**Date researched:** 2026-07-10
**Question:** Can Euangelion (a third-party web app on Cloudflare Workers) let end users authenticate with their existing consumer AI subscription (Claude Pro/Max, ChatGPT Plus/Pro, Manus) so that Devotional Curator inference runs on the USER'S subscription instead of an app-held API key?
**Method:** Web search + fetches of official docs (Anthropic Claude Code / Agent SDK docs, Claude Help Center, OpenAI Codex/Apps SDK docs, OpenAI Help Center, Manus API docs, OpenRouter docs) plus reporting from 2025-2026. Every load-bearing claim is cited with URL and date.

---

## 1. Executive answer

| Provider               | Can Euangelion users sign in with their existing subscription today? | Classification                                                                                                                                                                                                                                                                         |
| ---------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Anthropic / Claude** | **NO** (partner-gated; forbidden without prior Anthropic approval)   | Officially supported surface EXISTS but only for "previously approved" partners. For everyone else: TECHNICALLY-POSSIBLE-BUT-FORBIDDEN, with active enforcement and account bans.                                                                                                      |
| **OpenAI / ChatGPT**   | **NO** (no GA program; pilot/interest-form only)                     | "Sign in with ChatGPT" for third-party apps has been an interest form since May 2025 and has not shipped as a self-serve product as of July 2026. Codex-token reuse in third parties is tolerated-but-uncommitted grey zone, and only for CLI-style local tools, not a hosted web app. |
| **Manus**              | **NO**                                                               | OAuth exists only for Team accounts, and only same-team members can authorize an app. No consumer sign-in program at all.                                                                                                                                                              |

**Bottom line:** As of 2026-07-10, there is no provider where a random third-party web app can self-serve register an OAuth client and let consumers' existing AI subscriptions pay for inference inside that app. The closest ToS-compliant, zero-approval mechanism that shifts inference cost to the user is **OpenRouter's OAuth PKCE flow** — but that means users connect an OpenRouter account (new account + their own credits), not their existing Claude/ChatGPT subscription.

## 2. Anthropic / Claude — detail

### (a) Officially supported surface

- **Claude subscription OAuth is restricted to Anthropic's own surfaces plus previously-approved partners.** The official Agent SDK docs state, verbatim:

  > "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Please use the API key authentication methods described in this document instead."

  Source: [Agent SDK overview — code.claude.com](https://code.claude.com/docs/en/agent-sdk/overview) (official, accessed 2026-07-10).

- A sanctioned "third-party apps sign in with Claude" surface **does exist** — Anthropic's own Help Center describes "Third-party apps that authenticate with your Claude subscription through the Agent SDK" and a planned monthly **Agent SDK credit** (Pro $20 / Max 5x $100 / Max 20x $200) to cover it. That billing change was **announced May 2026 and paused on June 15, 2026** ("For now, nothing has changed: Claude Agent SDK, `claude -p`, and third-party app usage still draw from your subscription's usage limits"). Source: [Use the Claude Agent SDK with your Claude plan — Claude Help Center](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan) (official, accessed 2026-07-10); corroborated by [Zed's blog on the change + June 16 pause update](https://zed.dev/blog/anthropic-subscription-changes).
- But that surface is **partner-gated, not self-serve**. There is **no public OAuth client registration** for "Sign in with Claude." The entry path is Anthropic's partner network / sales ([partnerportal.anthropic.com registration](https://partnerportal.anthropic.com/s/partner-registration)) — an application with no published criteria or timeline. Independent write-ups confirm Anthropic "does not provide a way to register new client IDs for third-party projects" ([Moltis FAQ](https://docs.moltis.org/anthropic-oauth.html); consistent with the Agent SDK docs note above).
- Early-2026 billing note: for the apps that ARE approved, third-party usage moved from plan-included usage to a prepaid **"extra usage credits"** pool ([fazm.ai overview of the third-party app program](https://fazm.ai/blog/claude-third-party-apps), third-party source, 2026).

### (b) Technically possible but ToS-violating

- `claude setup-token` produces a long-lived subscription OAuth token (`CLAUDE_CODE_OAUTH_TOKEN`) intended for the subscriber's own CI pipelines — "scoped to inference only," Pro/Max/Team/Enterprise ([Claude Code authentication docs](https://code.claude.com/docs/en/authentication), official). Harvesting such tokens from users (or having users paste them into Euangelion) to run server-side inference is exactly what Anthropic prohibited:
  > "Using OAuth tokens obtained through Claude Free, Pro, or Max accounts in any other product, tool, or service, including the Agent SDK, is not permitted and constitutes a violation of the Consumer Terms of Service."
  > Documented in Anthropic's legal/compliance update of Feb 19, 2026; enforcement began Jan 9, 2026 (blocked Max OAuth in third-party clients, developer bans reported). Sources: [WinBuzzer, Feb 19 2026](https://winbuzzer.com/2026/02/19/anthropic-bans-claude-subscription-oauth-in-third-party-apps-xcxwbn/); [VentureBeat on the crackdown](https://venturebeat.com/technology/anthropic-cracks-down-on-unauthorized-claude-usage-by-third-party-harnesses). Anthropic spokesperson: "Using Claude subscriptions with third-party tools isn't permitted under our Terms of Service, and they put an outsized strain on our systems" ([MindStudio, 2026](https://www.mindstudio.ai/blog/openai-codex-anthropic-subscription-change)).
- Enforcement is technical, not just legal: since ~Apr 4, 2026 Anthropic fingerprints the client and "rejects anything that is not the genuine Claude Code binary authenticating with an approved OAuth session" ([Kersai guide, 2026](https://kersai.com/anthropic-killed-third-party-claude-access-heres-every-workaround-that-still-works/), third-party source). So even the forbidden path is being actively closed and risks banning the USER'S account — unacceptable for a devotional product.

### (c) Verdict for Euangelion

**NO today.** The only legitimate route is applying to Anthropic for partner approval (sales/partner portal) — a waitlist/approval process with unknown criteria, i.e. not implementable today. The compliant self-serve route Anthropic itself points to is **API keys** (what Euangelion already does with its Workers-held `ANTHROPIC_API_KEY`).

### Related but different: Claude custom connectors (MCP)

Anthropic DOES officially support the **inverse** direction today, self-serve: Euangelion could host a **remote MCP server** and users on Free/Pro/Max/Team/Enterprise add it to Claude.ai/Desktop as a **custom connector** (Settings > Connectors > Add custom connector, by URL — Free users get 1 connector). Inference then runs inside Claude on the user's subscription; Euangelion supplies devotional content/tools. Sources: [Get started with custom connectors using remote MCP — Claude Help Center](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp); [Build custom connectors via remote MCP servers](https://support.claude.com/en/articles/11503834-build-custom-connectors-via-remote-mcp-servers) (both official). Caveat: the experience lives in Claude's UI, not on euangelion.app, and Claude connects to the MCP server from Anthropic's cloud (server must be publicly reachable).

## 3. OpenAI / ChatGPT — detail

### (a) Officially supported surface

- **"Sign in with ChatGPT" for third-party apps is NOT generally available.** OpenAI began gauging developer interest in May 2025 ([TechCrunch, May 27 2025](https://techcrunch.com/2025/05/27/openai-may-soon-let-you-sign-in-with-chatgpt-for-other-apps/)) and piloted it in its own Codex CLI, where signing in grants identity plus a one-time API-credit bonus ($5 Plus / $50 Pro) — not ongoing subscription-powered inference for arbitrary apps ([Medianama, June 2025](https://www.medianama.com/2025/06/223-openai-sign-in-with-chatgpt-third-party-apps/)). As of July 2026 there is still no public developer documentation or self-serve client registration; the ask remains an **open feature request** on OpenAI's own tracker ([openai/codex issue #10974](https://github.com/openai/codex/issues/10974)), and a June 26, 2026 community-built "Login with ChatGPT" demo went viral precisely because no official product exists ([Explainx write-up, 2026](https://www.explainx.ai/blog/login-with-chatgpt-codex-subscription-oauth-2026)).
- **What IS official:** Codex sign-in with ChatGPT covers the **account holder's own** usage across OpenAI's surfaces — ChatGPT web/desktop, Codex CLI, IDE extension, Codex cloud, and the **Codex SDK** (available on Plus/Pro/Business/Edu/Enterprise). Sources: [Codex authentication docs](https://developers.openai.com/codex/auth) (official; redirects to learn.chatgpt.com/docs/auth); [Using Codex with your ChatGPT plan — OpenAI Help Center](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan) (official). This means the FOUNDER could run Codex under the founder's ChatGPT plan — it does not let Euangelion's END USERS bring their plans to euangelion.app.
- **Codex App Server** (embedding Codex in your own product with auth/history/approvals) exists but custom integrations must "contact OpenAI to get added to a known clients list" — i.e., approval-gated, not self-serve ([Codex App Server docs](https://developers.openai.com/codex/app-server), official, accessed 2026-07-10).
- **Apps in ChatGPT (Apps SDK):** launched Oct 2025, open submissions since Dec 17, 2025 with review; the app is an MCP server the developer hosts, the model conversation happens inside ChatGPT on the user's plan, and the OAuth goes the OTHER direction (users link the APP'S account into ChatGPT via OAuth 2.1 + PKCE + dynamic client registration). Sources: [Introducing apps in ChatGPT — OpenAI](https://openai.com/index/introducing-apps-in-chatgpt/) (Oct 2025); [Developers can now submit apps to ChatGPT — OpenAI](https://openai.com/index/developers-can-now-submit-apps-to-chatgpt/) (Dec 2025); [Apps SDK auth docs](https://developers.openai.com/apps-sdk/build/auth) (official); [VentureBeat](https://venturebeat.com/technology/openai-now-accepting-chatgpt-app-submissions-from-third-party-devs-launches). Like Claude connectors, this puts Euangelion INSIDE ChatGPT rather than the user's subscription inside Euangelion.

### (b) Technically possible but grey/uncommitted

- Community tooling reuses locally-cached Codex OAuth tokens (`~/.codex/auth.json`) against `chatgpt.com/backend-api/codex/responses` to get plan-billed inference programmatically (the so-called "Codex Subscription API," documented after GPT-5.5's Apr 23, 2026 launch). It is **reverse-engineered, undocumented, no SLA**, though OpenAI has been publicly tolerant — "We want people to be able to use Codex, and their ChatGPT subscription, wherever they like" — and unlike Anthropic has not blocked third-party harnesses. Sources: [Codex Subscription API analysis, Apr 24 2026](https://codex.danielvaughan.com/2026/04/24/codex-subscription-api-programmatic-access-gpt-5-5-chatgpt-plan/); [Manifest blog on third-party harnesses](https://manifest.build/blog/chatgpt-plus-tokens-third-party-harnesses/) ("Nothing in OpenAI's terms of use explicitly permits or prohibits using your ChatGPT subscription inside a non-OpenAI tool. It reads like something they tolerate, not something they've committed to"); [MindStudio comparison](https://www.mindstudio.ai/blog/anthropic-restricts-third-party-agents-openai-opens-codex-comparison).
- For a hosted consumer web app this path is worse than grey: it would require Euangelion to collect/store users' ChatGPT OAuth tokens server-side (tokens that "carry your full workspace permissions"), against an endpoint that can change without notice. Not shippable for this product under project rule "no silent fallbacks / full implementation."

### (c) Verdict for Euangelion

**NO today.** No GA "Sign in with ChatGPT" program; Codex embedding is approval-gated; the tolerated token-reuse path is undocumented, uncommitted, and inappropriate to build a hosted product on. Watch item: OpenAI is the provider most likely to ship this — the interest form, the Codex pilot, and public statements all point that direction.

## 4. Manus — detail

- Manus's API authenticates with **API keys** (personal integrations — credits bill to the key owner's Manus account) or **OAuth2 for third-party apps**, but the docs are explicit: "Open App creation and authorization require a Team account. Only users in the same team as the app creator can authorize the app." That is an intra-team mechanism, not a consumer sign-in program. Source: [Manus API authentication docs](https://open.manus.ai/docs/v2/authentication) (official, accessed 2026-07-10).
- Manus consumer plans are credit-based (Free 300 daily credits; paid plans $20-$200/mo with monthly credit allotments), and API usage consumes the account's credits — there is no mechanism for an outside app's users to bring those credits to the app. Sources: [Manus Plans and Pricing docs](https://manus.im/docs/introduction/plans) (official); [Manus pricing overview, June 2026](https://www.nocode.mba/articles/manus-ai-pricing).
- No "Sign in with Manus" program, directory, or announcement found anywhere.

**Verdict: NO — confirmed none.**

## 6. Recommendation — tradeoffs for the founder (per project rule: presenting options, not deciding)

The core ask — "users sign in with the subscription they already pay for, inside euangelion.app" — is not purchasable today at any price of engineering effort. The real decision is which second-best posture to take:

**Option 1 — Keep the app-held key (A), add cost rails, revisit quarterly.**

- Gives up: nothing UX-wise; founder absorbs inference cost that scales with users.
- Gets: zero friction, full model quality, fully compliant, already built.
- Watch: OpenAI "Sign in with ChatGPT" GA and Anthropic's (paused) Agent SDK credit program are both moving; if either opens self-serve, this research should be redone — the landscape changed three times in the first half of 2026 alone.

**Option 2 — A + optional OpenRouter connect (B) for power users.**

- Gives up: some settings-screen complexity; a minority-audience feature; OpenRouter is a new account, not their Claude/ChatGPT plan.
- Gets: a genuine, ToS-clean "your usage, your bill" path that caps founder cost exposure; implementable this week with no signups by the founder (PKCE needs no client registration).

**Option 3 — A + Euangelion-as-connector (D) as a distribution play.**

- Gives up: control of the surface (experience lives inside Claude/ChatGPT); real build cost for a public MCP server; it does not power the on-site Curator.
- Gets: the ONLY officially-supported way today for users' existing subscriptions to fund Euangelion-branded AI interactions; potential discovery channel (ChatGPT app directory).

**Option 4 — Pursue Anthropic partner approval (E) in parallel with any of the above.**

- Gives up: founder time on an application with unknown odds/timeline; likely aimed at larger partners (Cursor-class).
- Gets: if granted, the exact product the founder asked about — "Sign in with Claude" on euangelion.app.

What is NOT on the table under this project's rules: Option G (token harvesting/reuse). Anthropic bans accounts for it and OpenAI's tolerance is explicitly uncommitted; either would put users' personal subscriptions at risk inside a devotional product.

## 7. Decision gate verdict

Question: does a fully supported, ToS-compliant path exist TODAY for end users to sign in with their existing Claude, ChatGPT, or Manus subscription and power Euangelion's on-site LLM features — with zero founder signups, waitlists, or partner applications?

**A fully supported, ToS-compliant, zero-founder-input path exists: NO.**

- Anthropic: partner approval required ("Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login").
- OpenAI: no GA third-party program (interest form since May 2025; Codex App Server requires contacting OpenAI).
- Manus: no consumer OAuth program at all (Team-only, same-team).
- The nearest zero-founder-input alternative (OpenRouter PKCE) uses a NEW user account with user-funded credits — it does not satisfy "existing subscription."

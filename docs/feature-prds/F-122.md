## 1. The failing test was stale, not a regression

`__tests__/daily-bread-why-this.test.tsx` → _"DailyBreadView: no session
payloads → no why-row"_ asserted on the day title, `The Name You Answer To`.

The file mocks `DevotionalHeadline` to `null`:

```ts
vi.mock('@/components/devotional/DevotionalHeadline', () => ({
  default: () => null,
}))
```

That mock was harmless when it landed (`45ad0ecd`), because `DailyBreadView`
rendered the title in its own `<h1>`. **SA-045 (F-091, `6bd9d419`)** then moved
the title into `DevotionalHeadline` so a plan day would read like a devotional —
and the assertion started reaching for text the mock had removed. The test has
been red since 2026-08-15.

The product is fine: the title renders on `/daily-bread`. Verified the component
still emits `<h1 className="devotional-headline-title">{typographer(title)}</h1>`
and that the title is simply absent from this test's DOM because of the mock.

Re-anchored on `scriptureText` from the same day fixture, which the reader does
render and which proves the same thing the title did: real day content reached
the page. The `why-row` assertion — the actual subject of the test — is
untouched.

## 2. Eight lint warnings, none of them cosmetic-only

Each was checked for a dropped call before anything was deleted, because an
unused import can mean "dead" or can mean "someone removed the call site".

| Warning                                          | Finding                                                                                           | Action                                  |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------- | --------------------------------------- |
| `withRedLetter` unused ×2, `resolveRedLetter` ×1 | All three files import both helpers and use exactly one. Red letter **is** applied in each.       | Trimmed the unused half                 |
| `getSelectionWithFallback` in `select/route.ts`  | The route only ever calls `saveSelection`; it writes, never reads                                 | Removed import                          |
| `editionSlug` in `daily-bread/page.tsx`          | Computed, never rendered. `volume`/`dayOfYear` do render (`Vol. N · No. N`)                       | Removed value + now-unused import       |
| `PlanRecord` in `plan-queries.ts`                | Type imported, never referenced                                                                   | Removed                                 |
| `useMemo` missing dep `series` (Bible 365)       | False positive — `Array<typeof series.days>` reads as a use of `series`                           | Typed as `Array<SeriesInfo['days']>`    |
| `_isDayUnlockedOriginal` in `day-gating.ts`      | **Deliberately kept.** The file's own comment: _"Reference implementation kept for restoration."_ | Honoured `^_` for vars in eslint config |

The last one is the important one: deleting it to satisfy the linter would have
thrown away the documented path back to day pacing. `argsIgnorePattern: '^_'`
was already configured, so `varsIgnorePattern: '^_'` follows the convention the
codebase had already chosen rather than inventing an exemption.

## 3. Generated artifacts that had drifted out of git

- `src/data/devotional-teasers.ts` is written by
  `scripts/generate-devotional-teasers.mjs` during `npm run build`. Its
  1,682-line diff was almost entirely quote style — the generator emits
  `'…\'…'`, prettier rewrites to `"…'…"` — over an identical 1,144 entries.
  Running prettier collapsed it to **one real change**: the `rekindled-day-1`
  teaser, regenerated from the day-1 text corrected in SA-075. Verified the live
  devotional JSON already carries that corrected wording, so the committed
  teaser now matches what production serves.

  Normalising the committed file was **not sufficient** — the next `npm run
build` re-emitted the raw form and dirtied the tree again, which is how this
  drift kept coming back. Caught by re-running the build after committing. The
  generator now formats its output through prettier (resolving the repo config)
  before writing, so what it emits is byte-identical to what the pre-commit hook
  would produce. Verified idempotent: two consecutive runs leave the tree clean.

- `scripts/red-letter/coverage.txt` is a dry-run report. It moved 153→157
  modules and 93→96 tagged, which is Rekindled's seven days entering the corpus.

## 4. The four unpushed commits were needed

Cross-referenced against the live site rather than assumed. Every one of the 20
Rekindled content assets in those commits — 7 devotional JSONs, 7 audio files, 4
videos, 2 images — is **byte-identical to production** (sha256, fetched live).

That means production was deployed from a local tree and the commits were never
pushed: the work is live but unrecorded in `origin/main`. Discarding them would
have deleted the only source record of content the site is already serving. They
are pushed, not dropped.

`public/sw.js` initially appeared to differ; a byte diff against the live file
showed it identical (a transfer-encoding artefact in the first hash).

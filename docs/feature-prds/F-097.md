## Problem

Founder, 2026-08-16:

> "Feature style- Try something different here- make it feel like a literal
> newspaper grid, with different sized stories etc. Rack doesnt feel like a news
> paper rack enough and I think there are too many columns. Spine should have
> several rows of books and the spines can be larger. No overflow scroll, all on
> page visible. Seperately, this needs a menu link: https://euangelion.app/today
> and I want it to be like a literally daily edition of a newspaper, and to be
> structured the same way- include more information here- not just a devotional,
> but like this is a place where people can come for daily content- this can
> pull in stories of christ around the globe, showcase community efforts, prayer
> lists etc. Eventually page will be customizable by user. This is distinct from
> the devotional reader."

Three of the seven Reading Room views were print-shaped in name only, and
`/today` was an unlinked page that rendered a devotional — not an edition.

## Solution

**Feature — a front page, not a bento.** A broadsheet allocates space by
importance, so the view does the same: a LEAD with a 21:9 plate and a banner
headline, two boxed SECOND stories separated by a column rule, a ruled RAIL of
briefs, then the remainder set as four columns of listings. Size is an editorial
statement about the series, not decoration.

**Rack — four papers to a rail.** At six, each paper was a sliver. At four it is
wide enough to read as a folded front page: masthead, rule, plate, standfirst,
in the order a real front page uses.

**Spines — shelves, not a scrollbar.** Twelve to a shelf, each shelf on its own
board, wrapping rather than scrolling, spines widened to 104–190px so a row
fills instead of trailing into whitespace. Width still encodes length.

**`/today` — the Daily Edition, with a nav entry.** Masthead with the
thin-over-thick double rule; a dateline carrying Vol/No derived from the date
(same day, same edition, for every reader) plus the real liturgical day; a front
page of lead story and an "Also in this edition" rail; then the full reading.

## The editorial sections are declared and empty, on purpose

Dispatches, Community and the prayer list have no data source in this repo —
there is no feed of global reports and no submissions table. `src/data/daily-edition.ts`
declares and types them, and each renders **only** when it carries real entries;
an empty section is absent, with no placeholder card and no "coming soon".

Inventing a dispatch from Nigeria or a prayer request would publish fiction as
fact, under a masthead, in a devotional context — the one failure this product
cannot afford. Every `Dispatch` requires a `source`, because an unattributed
report is a rumour.

## Contract

- SA-033 still holds. DAILY BREAD means *your* devotional; TODAY is the edition.
  They are different destinations, so the nav no longer duplicates.
- Vol/No is derived from the date, never random and never per-session.
- Editorial sections render only when populated; they never render placeholders.

## Platform Contracts

### Desktop

- Feature: a 12-column front page — lead spanning eight, seconds four each with
  a column rule between, brief rail full width, listings in four columns.
- Rack: four papers per rail, each wide enough to carry a masthead and
  standfirst without truncation.
- Spines: twelve per shelf, shelves wrapping down the page, no horizontal
  scroll at any width.
- `/today`: masthead centred, dateline as a single ruled line, front page as
  lead plus a two-column "Also in this edition" rail.

### Mobile

- Feature: the grid collapses to a single column in importance order — lead,
  seconds, briefs, listings — so the hierarchy survives the reflow.
- Rack: rails become one paper per row rather than shrinking to slivers.
- Spines: shelves reflow to fewer spines per board; still no sideways scroll.
- `/today`: masthead and dateline stack; the reading remains the anchor and is
  reachable from the lead without scrolling past editorial sections.

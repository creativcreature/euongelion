# F-123: Chat billed at OpenAI rates while Claude served the request

## Metadata

- Feature ID: F-123
- Category: Platform
- Owner: founder
- Status: shipped (2026-08-17)
- Decision: SA-079
- Surfaces: `/api/chat`, `/api/chat/usage`, brain router cost ledger

## Problem

The founder asked what the site costs to run. Measuring it surfaced a defect:
**the chat path bills Claude traffic at OpenAI's prices.**

`estimateCostUsd` priced a call from the _routing slot_ it went through, not the
engine that actually served it. The `openai` slot dispatches on key shape —
`router.ts` → `executeProvider`:

```ts
if (params.provider === 'openai') {
  result = isAnthropicKey(params.apiKey)   // 'sk-ant-…'
    ? await callAnthropic({ … })           // ← Claude
    : await callOpenAI({ … })
}
```

With the platform key (`ANTHROPIC_API_KEY`) that branch always runs Claude
Sonnet 4.6 against `api.anthropic.com` — and `sortClaudeFirstThenCheapest`
confirms the slot's real identity in code, testing `unique.includes('openai')`
to decide whether Claude is available. But both branches were then priced from
the same `openai` profile: **$0.05 / $0.40** per MTok, against Sonnet 4.6's real
**$3 / $15**.

Token counts were never the problem — `executeProvider` already prefers real
`usage` from the provider response. Only the rate was wrong.

### What it cost in practice

For a typical chat message (~3,000 in / ~700 out):

|                             | Input    | Output   | Total        |
| --------------------------- | -------- | -------- | ------------ |
| Recorded (`openai` profile) | $0.00015 | $0.00028 | **$0.00043** |
| Real (Sonnet 4.6)           | $0.0090  | $0.0105  | **$0.0195**  |

A **~45× understatement**. `/api/chat/usage` reports
`platformBudget: {limitUsd: 100}`, so the guard meant to stop spend at $100
would not have tripped until roughly **$4,500** of real spend.

### Scope: chat only

The generation path was already correct, and had already diagnosed this.
`soul-audit/cost-ledger.ts` computes USD from real token counts at Anthropic
rates, is written to Supabase, and backs a real budget cap — and its header
comment names the router as the outstanding bug:

> "the brain router's generic `estimateCostUsd` (cost.ts) uses a cheap-provider
> profile that UNDER-bills Anthropic by ~60x. Sonnet 4.x is $3 / $15 per MTok."

So the expensive path (devotional generation, ~$0.07/day, ~$0.48 per 7-day plan)
was always priced honestly and gated. Only chat under-billed.

## The fix

Bill by the **engine**, not the slot.

- `cost.ts` gains a `BillingEngine` type (`'anthropic'` plus the existing
  provider slots) and an `engineProfile()` that returns Anthropic's real rates.
- Those rates read the **same env overrides** as the Soul Audit ledger
  (`SOUL_AUDIT_INPUT_USD_PER_MTOK` / `..._OUTPUT_...`, defaulting to 3 / 15), so
  repointing the routed model moves both ledgers together and they cannot drift.
- `executeProvider` resolves `billedAs` at the point it already branches on key
  shape, and passes it to `estimateCostUsd`.

`providerBaseCostRank` is deliberately **unchanged**. It ranks routing slots for
`sortByCheapest`, and re-ranking Claude by its true cost would reorder the
fallback chain — a behavioural change nobody asked for. Ranking is not billing.

### Why this shape rather than renaming the slot

Renaming `'openai'` → `'anthropic'` across the union touches 9 files and changes
the public shape of `/api/brain/providers`, the settings UI, and stored user
preferences. It is also the wrong primitive: the slot is genuinely polymorphic —
under BYOK the same slot will serve a user's `sk-ant-` key _or_ their OpenAI key,
and must price each correctly. Billing by engine is correct for both today and
after BYOK; renaming is cosmetic and would still need this fix underneath.

## Contracts

### Desktop

- No user-visible change. Billing accuracy only.

### Mobile

- No user-visible change.

### Both

- A call is priced by the engine that served it. A routing slot is never
  assumed to imply a price.
- Anthropic rates in the router and in `soul-audit/cost-ledger.ts` resolve from
  the same environment variables.

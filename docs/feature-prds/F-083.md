## User Expectation

- Saving a devotional and activating it makes it THE devotional Daily Bread shows — surviving reloads, new sessions, and new devices — and never silently reverting to the "A Voice in the Wilderness" empty-state card.

## Root Cause (diagnosed 2026-07-27)

- Migration `database/migrations/013_create_active_series.sql` was NEVER applied to production Supabase: `active_series`, `scheduled_series_swap`, and `archived_series` do not exist (verified by REST probe — PGRST205 on all three; `session_bookmarks` and `devotional_plan_instances` exist).
- `src/lib/library/repository.ts` wrote the in-memory Workers-isolate cache first, then swallowed the failing Supabase upsert (console.error only) — so `PUT /api/devotionals/active` returned `ok: true` from memory. The activation "worked" until the next request hit a different/recycled isolate, at which point the row never existed and `/daily-bread` fell through to `EmptyState` (which renders the What Is the Gospel Day 1 card, titled "A Voice in the Wilderness").
- Same failure class as the 2026-07-22 accounts diagnosis: dashboard/database state drift, invisible because the code degraded silently.

## Root Cause #2 (diagnosed 2026-07-27, same day)

- After the tables were created, the founder still saw a stale devotional: `src/proxy.ts` — deleted 2026-05-07 with its route gating — was ALSO the only place the Supabase session could be refreshed with persistable cookies. Server Components cannot write cookies, so once the access token expired (~1h) every RSC render went auth-blind: `/daily-bread`'s `getUser()` returned null, the page ignored the user's `active_series` row, and fell through to the stale Soul Audit plan (a work-worry theme rendering a "kingdom of heaven" reading) or the empty state. API route handlers CAN persist refreshed cookies, so writes kept "working" while page reads intermittently forgot the user — the confusing half-working behavior reported since May.
- Fix: restored session refresh as `src/middleware.ts` (edge). Next 16's `proxy.ts` is Node-runtime-only and `@opennextjs/cloudflare` hard-fails Node middleware; the legacy `middleware` convention still compiles as edge middleware, the only flavor the Workers adapter supports. Matcher scoped to `/daily-bread`, `/library/*`, `/onboarding`, `/admin/*`.
- UI hardening: `LibraryView` and `SeriesActions` start-flows silently ignored `needsAuth` and error results (a failed activation looked like success) — both now toast honestly, matching `DevotionalActions`.

## 10/10 Definition

- Migration 013 applied; activation persists across reloads/isolates/devices.
- NO SILENT FALLBACKS (dev rule #1): every user-intent write (activate, day bump, archive, queue swap, clear, restart) throws `LibraryPersistenceError` when the Supabase write does not land, rolls the in-memory cache back so same-isolate reads cannot lie, and the API returns an honest 503 `PERSISTENCE_FAILED` with user-readable copy.
- Render paths (`promoteScheduledSwapIfDue`, `touchActiveSeries`) never 500 a page on a failed lazy write — they log, roll back, and serve the un-promoted truth.
- Regression suite encodes the contract (`__tests__/library-repository-persistence.test.ts`).
- Canonical reads distinguish an absent row from an unavailable database. A read/auth failure reaches the route error boundary; it can never impersonate "no active devotional."
- Current-plan consumers (`/api/soul-audit/current`, header badges, returning-user surfaces) resolve `active_series` before any older Soul Audit history.
- Client state retains the last confirmed active devotional through transient read failures and clears it only on a confirmed anonymous/empty response.

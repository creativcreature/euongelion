# F-141: /today can finish a day of a curated series

## Metadata

- Feature ID: F-141
- Category: Platform
- Owner: founder
- Status: shipped (2026-08-19)
- Decision: SA-095
- Surfaces: /today (curated series reader)

## Problem

Founder, 2026-08-19: _"When I finish day one and move on, it keeps making day
one the active. There needs to be a way to mark a devotional done in a series so
that the series can automatically keep moving."_

`/today` has **two** readers, and only one of them could finish anything:

| Path               | Reader              | Could finish a day?                  |
| ------------------ | ------------------- | ------------------------------------ |
| Soul Audit plan    | `DailyBreadView`    | Yes — MARK DAY COMPLETE, since F-066 |
| **Curated series** | `CuratedActiveView` | **No — nothing**                     |

On the curated path, `setActiveDay` is **local React state**. Moving to day 2
changed the view and nothing else: it evaporated on reload, and the server's
`active_series.current_day` sat at 1 forever. The only mark-read control in the
product lived on `/devotional/[slug]`, so a reader working through a curated
series — on the page built to hold their place — could never advance it.

The machinery was already there and already correct: `markDevotionalComplete`
calls `advanceActiveDayAfterCompletion`, which PATCHes `current_day` (F-097). It
simply had no caller on this surface. Half of that fix landed in August; this is
the other half.

## Fix

`CuratedActiveView` gains the completion control, with the same copy as
`/devotional/[slug]` so the two readers do not describe the same act in two
voices:

> Finished reading? Mark this day read. → **MARK READ & CONTINUE** · Next: {title}

Pressing it records the completion (which advances `current_day` server-side),
emits `libraryUpdated` so the library's ACTIVE card stops showing the day just
finished, moves the view to the next day, and refreshes.

Day chips gain a ✓ for days already read, so the strip shows what is **done**
rather than only what is **selected**.

Future days are deliberately **not** locked. Day-gating is founder-disabled, and
the reading-plan material is emphatic that guilt mechanics drive readers off.
Finishing is offered, never demanded.

## Verified

`__tests__/curated-active-mark-read.test.tsx`, mounting the real component:

- the control appears on the active day
- pressing it records the completion for **this** day — asserted on the slug,
  because completing the wrong day would advance the plan past unread material

Type-check clean; the existing daily-bread and progress suites stay green.

## Acceptance criteria

- [x] A curated-series day can be marked read from `/today`
- [x] Doing so advances the plan server-side, surviving reload
- [x] The completed day is the one on screen
- [x] Read days are visible in the day strip
- [x] Future days remain reachable — no gating

## Contracts

- The reading closes with a mark-read control that advances the series.

### Mobile

## 1. A fourth collapsed plate — `/daily-bread`

`.edition-guide-plate` had no `aspect-ratio` and no height while wrapping an
`<Image fill>`, so all three "How to read" Bible-reading guides rendered
**335 × 0**. The images were loaded and decoded — `complete === true`,
`naturalWidth > 0` — and invisible.

This is the same fault fixed in F-115 for four other classes. Found by sweeping
**every** `*-plate` / `*-thumb` / `*-art` rule in `globals.css` and checking each
for a declared height, rather than by looking at pages one at a time. Now
`aspect-ratio: 3 / 2`, matching its sibling `.edition-panel-plate`.

Sweep result: every remaining container class declares a height. The other
`BROKE` hits were `*-img` classes — `object-fit` children whose parent supplies
the height, which is correct — and `.illustration-plate`, which has no JSX
usage at all (dead CSS).

## 2. The mobile menu — the founder's repeated complaint

> "The menu doesnt work properly on mobile when scrolling."

Measured at 390px with the page scrolled to y=1500: the **panel itself was
fine** — `position: fixed`, `z-index: 300`, correct offset, visible. Two real
faults sat around it:

| Behaviour              | Before                       | After  |
| ---------------------- | ---------------------------- | ------ |
| Page scroll while open | **scrolls behind the panel** | locked |
| Tap outside to close   | **does nothing**             | closes |
| Escape to close        | works                        | works  |

Body scroll is frozen via `overflow: hidden` on **both `<html>` and `<body>`**,
restoring the previous values on close. Two corrections were needed to get this
right, both caught by measurement:

- **`<body>` alone does nothing.** `document.scrollingElement` here is the
  documentElement, so the page still scrolled — measured going from y=1400 to
  y=1900 with the panel "locked".
- **`touch-action: none` was wrong and was removed.** `touch-action` resolves by
  intersecting values down the ancestor chain, so setting it on the body would
  have won on the panel too and made the panel's own `overflow-y: auto`
  impossible to touch-scroll — trading one bug for another.

Deliberately **not** `position: fixed` on the body, which would jump the reader
back to the top when the menu closes.

The outside-tap handler ignores the toggle itself — otherwise the toggle's own
close would immediately be followed by a reopen.

## 3. Touch targets under 44px

CLAUDE.md requires ≥44px. Measured at 390px:

| Control                              | Rendered |
| ------------------------------------ | -------- |
| `.mock-icon-control` (theme, search) | 37 × 34  |
| `.rr-view` (series view toggles)     | 40 × 35  |
| `.rr-sort` (sort buttons)            | 39 × 25  |

These are dense, closely art-directed toolbars, so this does **not** resize
them. A transparent `::after` extends the _hit area_ to a 44px minimum and
leaves every visible pixel where it is. Scoped to `@media (pointer: coarse)` so
mouse hover regions are unchanged. Verified none of the three sits inside an
`overflow: hidden` container, which would clip the expanded area and make the
fix a no-op.

## 4. Escape now closes search from anywhere

`GlobalSearchOverlay` closes on Escape via a React `onKeyDown` **bound to the
panel**, so it only fires while focus is inside. Focus is normally moved to the
input on open — but that happens in a `requestAnimationFrame` and can lose the
race. Caught live with `document.activeElement` still on `BODY` and Escape doing
nothing, leaving the overlay closable only by mouse.

A second, reproducing run showed focus landing correctly, so this is
intermittent rather than always-broken. Rather than rewrite working focus logic
on an unreliable signal, a document-level Escape listener was added while open.
It is purely additive: it cannot break the panel-scoped path, it only covers the
case where focus never arrived.

## Audited and deliberately NOT changed

- **Three 401s per page load** (`/api/devotionals/{active,saved,archive}`) for
  signed-out readers on every series page. The 401 path is deliberate and
  documented in `devotionalLibraryStore.refresh()` — a 401 means "no
  account-scoped state". Gating the calls on `authStore.userId` would suppress
  real fetches for signed-in readers whenever the store had not initialised
  first, which is a far worse failure than console noise. Flagged, not touched.
- **Homepage `GET MATCHED`** at 141×38 — under 44px. Pre-existing, and the
  founder had just asked for CTAs to get _smaller_. Flagged for a ruling.
- **Dark mode** — 40 sampled text/surface pairs, zero below 4.5:1.
- **Homepage spacing** — no empty boxes, no unexplained gaps.
- **`/sunday`, `/pricing`, `/how-we-write`, `/series/[slug]`** — no overflow, no
  collapsed images, single `h1` each.

## 5. Three deeper faults the audits surfaced (round two)

### The menu bug's actual root cause

The scroll lock and outside-tap fixed real problems, but not the one the founder
kept reporting. Measured with the panel open at 390px:

```
topbar bottom edge : 56.0px
panel top          : 42.0px   ← hardcoded --mock-h-topbar fallback
overlap            : 14.0px
elementFromPoint(✕ lower edge) → DIV.mock-mobile-secondary-nav
toggleFullyClickable → false
```

**The open panel painted over the bottom third of its own close button**, and
taps there hit the panel instead. `z-index: 300` on the panel beats the topbar's
`120`, so the panel always won.

The cause: `.mock-mobile-menu-toggle` carried a real `min-height: 44px`, making
it the tallest child of the topbar row and pushing the bar to 56px — while
roughly ten rules, including the panel's own `top`, are written against
`var(--mock-h-topbar, 42px)`. The toggle is now a 2rem box with a transparent
44px `::after` hit area — the identical strategy its sibling icon controls
already use, and the one this file's own comment says was chosen specifically
so the hit target could clear 44px "without inflating … the 42px topbar".

### `viewport-fit=cover` was missing, so every safe-area inset was zero

There was **no `viewport` export anywhere in `src/app/`**, so Next emitted its
default viewport without `viewport-fit=cover` — and `env(safe-area-inset-*)`
resolves to `0` unless that is set. Roughly fifteen already-written safe-area
rules were inert: `--shell-safe-top`, the tab bar's home-indicator padding, the
menu panel's bottom inset, the cookie banner and the search overlay's notch
padding.

It matters most in the installed PWA, which ships `statusBarStyle:
'black-translucent'` with `display: standalone` — that extends the web view
under the status bar and _requires_ the insets to compensate. `public/ios-shell/index.html`
has had the incantation all along; it never made it into the Next app.
`maximumScale`/`userScalable` deliberately left alone so pinch-zoom still works.

### Nothing navigated between 768px and 900px

Measured at 834px (iPad portrait): `.mock-nav` `display: none`,
`.mock-topbar-desktop-row` `display: none`, `.mobile-tab-bar` `display: none`.
The desktop nav hides at ≤900px; the tab bar only appeared at ≤767px. In that
band the only navigation was the hamburger, which by design carries just
HOME / HELP / SIGN IN / SIGN UP.

The tab bar now turns on at ≤900px, exactly where the desktop nav turns off.
Crucially this moved the **whole mobile-shell cohort** together — the bar, its
installed-PWA padding, the mobile topbar toggle sizing, and everything
positioned to _clear_ the bar (cookie banner, reader-theme trigger, narration
controls). Moving the bar alone would have left those four sitting underneath
it between 768 and 900px.

## 6. A false privacy claim at the point of collection

The most serious finding of the night, and a direct hit on the founder's
"outdated and therefore untruthful" complaint — larger than the page named.

Four surfaces promised the Soul Audit reflection is **never stored**:
`src/app/page.tsx` (directly under the GET MATCHED button), `soul-audit/page.tsx`,
`about/page.tsx`, and `how-we-write/page.tsx` under a heading reading
**WHAT IS NEVER STORED**.

It is stored. Verified in the source, not inferred:

```
src/lib/soul-audit/repository.ts  createAuditRun()
  run = { session_token, response_text: params.responseText, … }
  await safeInsert('audit_runs', run)

database/migrations/009_create_soul_audit_tables.sql
  response_text TEXT NOT NULL
  CREATE INDEX idx_audit_runs_session ON audit_runs (session_token)
```

`src/lib/privacy/retention.ts` — which renders on `/privacy` — already states it
plainly: _"Our database, keyed by session token."_ Two pages on the same site
made opposite privacy representations about the same field, and the false one
sat at the moment of collection, about the most intimate data the product
handles.

All four now match the retention policy: used to compose the edition, kept with
the anonymous session for 30 days, then deleted; never sold, never shared, never
used to train AI. **The storage itself is fine** — RLS is locked down, the purge
exists. The defect was the representation, and only the representation was
changed.

## 7. Smaller fixes in the same pass

- **`.mock-btn` hover/focus was invisible in the default theme.** The shared rule
  paints `--mock-blue` on `--mock-paper`, and in dark those two plus `--mock-bg`
  are the same value (`#171b69`; `#000000` in night) — **1.00:1**. The icon
  control, account trigger and mobile toggle had dark rescues; `.mock-btn`,
  `.mock-account-item`, `.mock-carousel-btn` and `.mock-reset-btn` did not. And
  because `:focus-visible` shares that selector, **keyboard users lost the focus
  indicator entirely** on the app's primary button.
- **The global search input had no focus ring.** `outline: none` with no
  replacement, and it is _unlayered_ while the `input:focus-visible` fallback
  lives in `@layer base` — unlayered beats layered regardless of specificity, so
  the fallback never applied. Mirrors `.rr-search:focus-within`, which already
  solves this in the same file.
- **The homepage's dominant CTA promised "no account", then demanded one.**
  Both `READ TODAY'S PAGE` links pointed at `/today`, which hard-redirects to
  sign-in, under copy reading _"No setup, no account — just open it and read"_
  and a trust row reading `NO ACCOUNT`. Repointed to `/daily-bread`, the public
  edition the copy actually describes.
- **"Currently active: <your series>" opened the shared paper.** Both
  `DevotionalActions` and `SeriesActions` linked `/daily-bread` from a label
  naming _your_ series and day. Both already `router.push('/today')` elsewhere —
  the swap was applied to the programmatic navigation and missed on the Links.
- **Unlabelled controls.** The account trigger's entire accessible name was a
  single initial ("C, menu button"); both auth email inputs were
  placeholder-only with no `<label>` anywhere in either file — and those two
  fields _are_ the sign-in and sign-up flows.
- **Menu close on tap.** Nav links closed the panel only via the route-change
  effect, which no-ops when the destination equals the current route — so
  tapping HOME while on `/` left it open. Also closes now when the viewport
  grows past 900px, which previously stranded the panel with no ✕.

## 8. Left for a ruling — deliberately not changed overnight

- **Header and footer render _inside_ `<main>` on ~30 pages**, so the skip link
  skips nothing and there are no `banner`/`contentinfo` landmarks. Genuine WCAG
  2.4.1 failure and the single highest-leverage a11y fix available — but it
  touches 30 files while two other sessions are working, so it is a morning job.
- **`--color-gold` is amber in dark and cobalt in light.** The token's name
  asserts a colour it does not have, and that one lie has now produced the same
  contrast bug three times (SA-044, SA-047, and `.mock-btn` above). Renaming it
  and adding an `--on-accent` token is the durable fix.
- **The stylesheet is mostly unlayered.** `globals.css` has one
  `@layer utilities` block (lines ~2576–4002); the ~10,000 lines after it are
  unlayered and beat _every_ Tailwind utility regardless of specificity. That is
  why `mx-auto flex` lost to `.cta-major` earlier tonight. An audit found ~36
  further dead utility tokens across settings, the library page and the reader.
- **Three 401s per page load** for signed-out readers — deliberate and
  documented; gating on `authStore.userId` risks suppressing real fetches.
- **Two failing tests are the other session's**, not this work:
  `narration-manifest-current` is missing tracks for the seven new `rekindled`
  devotionals, and `daily-bread-why-this` broke via their edits to
  `src/data/series.ts`. Neither file was touched here and neither was staged.

## Problem

Founder, 2026-09-08, supplying the rule as written copy:

> "Mannered prose substitutes metaphor and flourish for direct statement. Instead
> of 'a parameter worth varying,' the mannered writer produces 'a dial worth
> turning.' Instead of 'this point still matters,' they write 'this point earns
> its keep.' The phrases exist to display the writer, not to convey the idea, and
> readers can tell. That is why mannered prose irritates: it makes the reader work
> harder so the writer can perform. It is also imprecise. Metaphors drag in
> connotations the writer did not choose and cannot control. The fix is to say
> what you mean. When a literal phrase is available, use it."

Directed at the devo-go writer **and overall site writing**, not devotionals alone.

## Solution

Tell 10 in the existing SA-128/SA-130 AI-tells system, which already had the right
shape: a canonical table in `AUTHORING-SPEC.md` §2, a mirror in
`AI-CONTENT-CONSTRAINTS.md` so the two cannot drift, quote-stripped mechanical
enforcement at NEEDS-FIX for the patterns that are safe to automate, and editorial
enforcement for the ones that are not.

**Site-wide** lands in `PUBLIC-FACING-LANGUAGE.md` — UI copy, emails, series
descriptions, the about page — with three rows added to its tone red-flag table.
That doc's core principle is that users should feel _met, not sorted_; a reader who
feels performed at does not feel met, so the rule follows from what was already
there.

## What is mechanical and what is not

The class cannot be regexed. A devotional is full of legitimate figurative
language and Scripture is figurative throughout; explaining a vine or a torn veil
IS the work. **The test is whether the figure CARRIES the idea or STANDS IN for
it** — if a plain phrase would say the same thing more exactly, the figure is
decoration.

What is safely mechanical is the stock business-flourish vocabulary, which has no
place in this voice and is never the clearest way to say anything: "earns its
keep", "does the heavy lifting", "punches above its weight", "moves the needle" /
"moves the dial", "secret sauce", "where the magic happens", "a masterclass in",
"lives and dies by", "the beating heart of", "connective tissue", "carries its
weight", "north star", "worth turning".

## Measure before landing a rule (SA-130 precedent)

All fifteen candidates were run against **596 shipped devotionals** before any was
written into the validator.

- Fourteen came back clean or near-clean: "earns its keep" 1 hit
  (`bible-365-day-2`), "does the heavy lifting" 2 (`bible-365-day-290`,
  `the-blueprint-of-community-day-4`), the other twelve zero.
- **"sings" was DROPPED.** It fired 22 times, because in a devotional people
  literally sing, in the Psalms. Shipping it would have made the rule noise, and a
  rule that fires on legitimate prose gets switched off and then protects nothing.

`drawing-near` (the most recent series) validates 0/0 against the shipped set.

## The gate that was silently dead

Found while looking up the next free feature id: `scripts/check-feature-prd-integrity.mjs`
was **0 bytes**, and had been since 2026-08-29, so `npm run verify:feature-prds`
had been passing trivially for nine days across every commit in the repo.

**Cause, and it is mine.** Three commits that night (`1119b856`, `f7d90c2e`,
`00eca6a5`) bumped the hard-coded count with

```python
open(path, 'w').write(open(path).read().replace(old, new))
```

`open(path, 'w')` truncates the file the moment it is evaluated, which happens
**before** the inner `open(path).read()` runs. So the read returned an empty
string and the write wrote nothing. Every gate reported OK afterwards, which is
exactly why it went unnoticed.

Restored from `1119b856~1` and the count corrected 171 → 177. On its first live
run it immediately caught a real defect that had shipped behind it: `F-178.md` was
missing both `## Methodology References` and its Desktop/Mobile contract. That PRD
now carries both, restated from its own content and labelled as structural.

**Guard:** never use that Python idiom again. `sed -i ''` or read-then-write as two
statements. The failure is silent by construction — the file is destroyed before
anything can notice.

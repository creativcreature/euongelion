## The press impression

The first attempt was a curtain: a solid panel that faded a word in and slid
away. Any site could wear it. This is the sequence only this masthead can make.

1. **Ink** — solid cobalt with the wordmark **knocked out** of it. The letters
   are paper showing through, not white type laid on top, because that is how
   the real thing prints.
2. **Set** — the word arrives over-tracked and tightens to final spacing, the
   way type is set into a stick.
3. **Register** — a crimson ghost sits a few pixels off and slides into
   alignment. Misregistration is this brand's actual signature, on every plate
   on the site, so the intro is made **out of** the identity rather than
   decorated with it.
4. **Hand off** — the ink lifts on a hard edge and the wordmark flies to the
   **measured** position and size of the real masthead. The intro _becomes_ the
   site instead of getting out of its way.

### Two calibrations, found by slowing it 6× and photographing it

- **The widest frame is the one that must fit.** At `10.5vw` with `0.34em`
  tracking the word ran off both edges — the over-tracked first frame, not the
  final one, sets the size ceiling.
- **The slip's own opacity keyframes override the shared fade-in.** Starting it
  at full strength made the crimson arrive before the cream, and the whole thing
  read as a red word. It fades in from zero and trails the key plate now.

### Safety (unchanged, non-negotiable)

Paints on top of a fully rendered page; `pointer-events: none` and `aria-hidden`
from the first frame; home only; once per session; skipped entirely under
`prefers-reduced-motion`; hard-stopped at 3.2s even if an animation never
resolves.

## The resume button

The banner already had `justify-items: center`, and I twice reported this done
on that basis. It was not centred.

The **copy** only looked centred because `text-align` was doing that job inside
full-width grid items — which masked the fact that item alignment never reached
the link at all. Diagnosed by forcing the resume state locally and photographing
it: the button sat hard left against the padding edge.

It now carries `justify-self`, `align-self` **and** `margin-inline: auto`, so it
holds whether that container is ever grid, flex or block.

**The lesson:** a rule being present in the stylesheet is not evidence the
element obeys it. Render the state and look.

## r2 — the hand-off had never run (2026-08-26)

**The founder's report:** "currently is stripped down basic and the colors
aren['t] working… the transition is currently choppy and ends awkwardly.
Mine[] is like 2/10."

He was right, and the cause was a cascade rule rather than a taste problem.

### Root cause, proven not inferred

`.press-word` carried `animation: press-set 900ms … both`. A **running
`fill: both` CSS animation outranks that element's own style attribute**, and
the component applied the hand-off flight as an inline transform. So r1
measured the masthead correctly on every load, at every viewport, in both
themes — and the browser discarded the answer.

Live DOM probe:

| Probe                      | Value                                           |
| -------------------------- | ----------------------------------------------- |
| inline `style` attribute   | `translate3d(-300px,-350px,0) scale(1.8)` (set) |
| computed `transform`       | `matrix(1.05846, 0, 0, 1, 0, 0)` (ignored)      |
| after `animation.cancel()` | `matrix(1.8, 0, 0, 1.8, -300, -350)`            |

**The wordmark never moved a pixel after t=888ms of a 1972ms sequence.** The
acceptance box above was ticked against a slow-motion viewing that cannot
distinguish "landed" from "never left".

Same cascade class silently killed three more things: the `.is-unmeasured`
fallback, `.is-lifting .press-word--slip { opacity: 0 }`, and `press-set`'s
tightening on the crimson plate (two animations sharing `transform`; the later
one wins).

### What the reader actually got

- 0ms: the finished homepage, fully painted, then covered — you cannot reveal
  what has already been read. Dark mode flashed black.
- 0–936ms: a static word on a flat rectangle. `scaleX(1.06→1)` is
  imperceptible; the crimson slip peaked at 0.26 alpha and never read. Three of
  four documented beats were invisible.
- 500–930ms: 430ms of dead hold — frames 391ms apart were pixel-identical.
- ~1300ms: the word desaturated through `rgb(180,178,201)`, bottoming out at
  **1.69:1** against the ink.
- The curtain retracted upward, so the page was revealed **bottom-first** — the
  first legible thing on screen was the cookie dialog; the masthead came last.
- 1454–1972ms: **two EUANGELION wordmarks on screen at once** (560ms in dark).
  On mobile the orphan landed on "A daily newspaper of the Gospel.", both
  typefaces overprinting into illegibility.
- ~1970ms: hard DOM removal at `opacity: 1` — a blink-out.

Also found: the in-app **Reduce Motion** setting was never checked (JS gated
only on the OS media query), turning that setting into a ~950ms full-screen
cobalt slab and a hard snap. And the flight target reflows 1128.7 → 1372.9px
when Industry loads — r1's fixed 950ms timer was lucky, not correct.

### r2 — the bug is now unrepresentable

- **Every beat is a script-created Web Animations API animation.** Script
  animations sort _above_ CSS animations and above all author declarations, so
  the sequence sits at the top of the cascade instead of the bottom.
- **The wordmark is a runtime clone** of `.js-shell-masthead-fit`, positioned
  at its measured rect and dressed in its _computed_ type contract, so
  `transform: none` **is** the masthead. r1 restated the type by hand and was
  ~4% off; there is now no landing number left to get wrong.
- **The colour change is spatial, not temporal** — two plates clipped by one
  shared edge scalar, so the word is one of exactly two colours at every
  instant and the lavender-mud frames cannot exist.
- **The wipe runs downward**, revealing in reading order: topbar, masthead,
  hero, cookie notice last.
- **The word lands congruent at 1260ms while the sheet still hides the real
  masthead**, so two wordmarks cannot compose; the ending is a dissolve onto a
  pixel-identical twin, which is a no-op at every alpha.
- The sheet is armed by a synchronous `<head>` script, so the first painted
  pixel is the sheet — and **both** reduced-motion signals are honoured before
  first paint.
- Measurement is gated on the header's own fit completing (a _ratio_ test,
  since the pre-fit rect is perfectly stable too), not on a timer.
- Three failsafes: a CSS `press-disarm` keyframe (zero-JS), the head script's
  3000ms self-disarm, and the component's `HARD_STOP_MS`.

| Invariants, light               | 2/6         | **6/6**                              |

### Platform contracts — r2

#### Desktop

- Set pose 0.86² of full measure; flight is a pure 239px rise (dx ≈ 0), landing
  congruent with the masthead at 1440×900 rect (33.5, 54.7, 1372.9, 204.0).
- Print stroke crosses the wordmark over 240ms.

#### Mobile

- Same sequence at 390×844; flight rise 291px onto rect (14.0, 53.3, 361.9,
  53.8). The wordmark never touches the positioning headline.

### The lesson

Slow-motion viewing told us the hand-off landed. A DOM probe told us it had
never started. Verify state, not appearance — and where a sequence has a
contract, write the test that can fail.

### Shipping note — v0.8.21 / SW v155

The intro changes the shell: `layout.tsx` gains the synchronous `press-arm`
script. A returning reader is served the cached shell until `CACHE_NAME` moves,
so this rides a release that bumps all three in step — `package.json` edition,
`sw.js` `CACHE_NAME`, and `SW_VERSION` in `ServiceWorkerRegistration`. The
client compares the stored version against `SW_VERSION`; a mismatch is what
makes it unregister, clear caches and re-register, so readers on the old build
pick the intro up without a manual hard-refresh.

## r2.1 — polish pass (2026-08-26)

Founder: "Its still a bit janky. Needs to [work] in both light and dark mode
and on both desktop and mobile."

Measured before changing anything. The motion itself was already clean — **zero
frames over 24ms during the flight or the wipe**, frame gaps 4.7-11.6ms. The
jank was structural, and it was three separate things.

### 1. ~430ms of dead air at the front

The sheet painted at 0ms and _nothing moved_ until 434ms. Instrumented the arm
to find out why:

| Milestone              | Dev       | Production      |
| ---------------------- | --------- | --------------- |
| Industry font resolved | 0ms       | 0ms (preloaded) |
| `document.fonts.ready` | 89ms      | 174ms           |
| **Masthead fitted**    | **428ms** | **429ms**       |

So it was never the fonts — `EuangelionShellHeader.fitAll()` is scheduled from
its own effect and therefore waits on React hydration. Dispatching a synthetic
`resize` to trigger the header's own listener was tried and **measured as no
help** (fitted stayed 432ms), because that listener is registered inside the
very effect hydration is gating. Re-deriving the fit ourselves would mean
predicting a post-fit rect from pre-fit metrics, and this design's whole value
is that the landing is exact rather than nearly right.

So the arm stays and the **sheet carries it**: the Ben-Day field now registers
in four discrete steps from the first painted frame (`press-ink-register`).
That is beat 0 — the press inking up — instead of a dead cobalt hold, and it
obeys the house texture rule that grain steps rather than glides
(`grain-drift` is `9s steps(6)`). Four repaints across the whole arm, not
sixty, so it cannot compete with hydration.

### 2. Dark mode still had no fourth beat

Photographed at the print stroke: the wordmark is cream _both sides_ of the
edge, because the knockout is cream and the dark masthead's wordmark is also
cream. Only the ground could change — and the sheet (`#1f2a8d`) against the
dark page ground (`#171b69`) measures **1.28:1**. The edge was very nearly
invisible. That is the exact criticism r1 earned, surviving into r2.

The dark sheet is now **lifted cobalt `#2236a2`** — 1.53:1 against the page,
and the brand's own documented dark-mode accent (`--color-cobalt-lifted`)
rather than an invented colour. The dot alpha is raised to 0.62 in dark as
well, so the texture step reinforces the luminance step: above the edge there
is no dot field at all. The arming sheet gets the same dark ground, or the
hand-over to the live overlay would show as a one-frame colour pop.

### 3. Too long

1720ms of sequence on a ~430ms arm meant the reader waited ~2.15s, and the
founder has now called the timing wrong three times across three versions.
Compressed to **1240ms**, landing the whole open at **~1.67s**. Every beat
keeps its shape and easing; only the clock is tighter. The print stroke is
deliberately _not_ scaled with the rest — it stays 220ms, because it is the
payoff and the one beat the eye must read rather than merely register.

## r3 — one word, one place (2026-08-26)

Founder: "you see the word twice during the animation. Its already there before
animations... currently its still looking extremely amature."

He was right, and it was **not a rendering fault**. I photographed the print
stroke at 2x and the letterforms are pixel-continuous across the ink edge; the
paper plate and the print plate measured `dy = 0.0px, dh = 0.0px` against each
other and 0.3px against the real masthead. Mechanically the previous version
was correct.

**The fault was the concept.** The masthead is a permanent element of this
page. Flying a second, centre-screen copy of it in and parking it on the first
means the reader genuinely does see the wordmark twice — and "logo flies in and
becomes the header" is a dated trope regardless of how well it is executed. No
amount of polish fixes a redundant idea.

The original brief never asked for the duplicate. Founder 2026-08-16: _"Show
euangelion first white on blue, then animate to system setting background… and
to normal site state."_ That is satisfied — better — by printing the masthead
**where it already lives**.

### What changed

The flight is gone. The wordmark is knocked out of the ink at the masthead's
own measured rect and stays there: the plate meets the paper fractionally
oversize (1.035) and 10px high, and settles into exact register. That is what a
press does, and it puts a second wordmark on screen at no point. Total travel
10px, inside the site's own ±28px cap; a uniform scale is not a distortion (the
dock already scales the masthead to 0.86).

Removing the flight leg also removed the clock it needed: **1240ms → 980ms of
sequence, ~1.42s end to end**, against 2.15s before today's work.

### The invariant that was missing

The old suite asserted "no two _separated_ visible wordmarks" — and passed,
because it only ever compared the clone to the real masthead, never asked
whether the clone had any business being where it was. Replaced with a
guarantee rather than a measurement:

> **INV7** — the wordmark's centre never leaves the real masthead's band
> (±40px) on any sampled frame.

Run against the previous designs it fails loudly, which is the founder's
complaint in numbers:

| Version             | INV7                                                             |
| ------------------- | ---------------------------------------------------------------- |
| r1 (original)       | FAIL — 230 samples stray, max **311px** from the masthead centre |
| r2.1 (this morning) | FAIL — 65 samples stray, max **240px**                           |
| r3 (this)           | PASS — one word, one place                                       |

### Verified

Invariants **7/7** on light, dark and mobile. Safety gates **7/7**. Degraded
paths **3/3**. Zero frames over 24ms during the sequence. Totals 1422 / 1433 /
1417ms (light / dark / mobile).

## r4 — the reference, finally seen (2026-08-27)

**I had been building without the brief.** The founder's 2026-08-24 instruction
lived in a commit message on `main`, on a branch this session never merged:

> "This is the intro animation I want [https://telhaclarke.com.au/]. I need 2
> versions - one for Darkmode, one for Light Mode. The Color of the euangelion
> needs to match the mode color. If Light Mode, Euangelion should be Blue, if
> Dark Mode it should be white."

Captured the reference this session. Its sequence: black field, meta text in the
corners with a live `Loading NN%`, the wordmark assembling by a **per-letter
vertical roll**, held, then the page arriving beneath it — the word never moves.
~4s total.

Two implementations existed and each had half the answer. Main's SA-127 had the
letter roll and the mode-correct colour but kept a flight to the masthead — the
"you see the word twice" the founder rejected on 2026-08-26. This branch's r3
had print-in-place but no roll and a cream word in both themes. Founder chose
the synthesis.

### What r4 is

- **The letter roll**, ported from SA-127 and re-expressed as script animations
  so it sits above CSS animations in the cascade (a CSS animation here is the
  exact class of bug that left the hand-off dead for two releases). 460ms with a
  26ms stagger — the reference's shape at the reference's ratio, against a clock
  the founder has already called mistimed three times.
- **The mode's own colours from frame one.** Ground = the page's own ground
  (`#f0ece6` light, `#171b69` dark); word = the masthead's own colour (cobalt
  light, cream dark). Because the intro's ground already equals the page's and
  the word already equals the masthead's, the curtain has nothing to reconcile:
  passing the masthead produces no visible change, so the two-plate colour split
  and the crimson register ghost were both retired.
- **Print-in-place, kept.** The word is at the masthead's measured rect for the
  whole sequence. INV7 holds.
- Founder ruled **no loading counter**: a counter on a warm cache flashes past,
  and a fake one is dishonest. ~1.6s end to end.

### Two things measurement caught that reading would not

1. **The mask must be one LINE BOX, not one em.** `height: 1em` is the font
   _size_; this masthead runs `line-height: 0.9`, so at the fitted 226.6px size
   an em-tall mask stands 22.7px proud of the real line box. The type-parity
   gate reported `dw: 0, dh: 23` — width exact, height wrong — and dropped the
   whole sequence to the sheet-only exit. `height: 1lh` tracks the cloned
   line-height and parity returned to 1373x204 on both.
2. **A settled roll column sits at −50%, not at 0.** The column is two faces
   tall and travels exactly one face. The first version of INV1 asserted it ends
   at zero, which would have been asserting the roll is half finished.

### Verified

Invariants **7/7** on light, dark and mobile. Safety gates **7/7**. Degraded
paths **3/3**. Test suite unchanged at its 3 known pre-existing failures.

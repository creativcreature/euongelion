# F-105: Two site states — signed out reads, signed in keeps

## Metadata

- Feature ID: F-105
- Category: Data & privacy
- Owner: founder
- Status: wip
- Decision: SA-062
- Surfaces: `/today`, `/library`, `/api/bookmarks`, `/api/annotations`, reader writing controls

## Problem

Founder, 2026-08-16:

> "Need two site states — one for signed in and one not signed in. Having an
> account enables notes, saving features, highlights etc. No account, data
> should not be retained… The unsigned in state simply is a reader,
> non-interactive and non saving."

The product had a third state nobody had designed on purpose: signed-out
readers accumulated highlights in `localStorage` and bookmarks under an
anonymous session token. Their work looked kept, was invisible to their account
if they ever made one, and vanished when the browser was cleared.

## Solution

**"Non-interactive" is scoped to non-SAVING** (founder-accepted amendment). The
catalog stays fully readable and listenable signed out — audio, chapters, speed,
translation, theme, the comprehension modules — because that is what earns the
account. What changes is that nothing the reader AUTHORS is kept anywhere.

**Locked, not hidden.** A save control that vanishes never teaches the reader
the product does that, and loses the best conversion moment there is: someone
moved by a line, reaching to mark it. Controls stay visible; activating one
opens sign-in with the intent recorded.

**The nav is deliberately NOT filtered.** Hiding `TODAY` and `LIBRARY` when
signed out would flash on every load (the header resolves auth client-side) and
would contradict locked-not-hidden. The route gates carry the redirect instead,
so clicking either lands on sign-in with the destination preserved.

**Gating follows MEANING, not the string.** SA-059 swapped the two reading
routes: `/daily-bread` is the shared paper (open), `/today` is the reader's own
plan (gated). An earlier draft of this feature had it exactly backwards.

## Contracts

### Desktop

- `/today` and `/library` redirect to `/auth/sign-in?redirect=…` when signed out.
- `/api/bookmarks` returns `AUTH_REQUIRED_SAVE_STATE` on all three methods.
- No writing control renders an input before auth is known (fail closed).

### Mobile

- Same gates; the redirect preserves the destination so a phone reader is not
  dropped on the home page.
- Tested at 375 / 768 / 1024.

## Acceptance Criteria

1. Signed out, nothing authored reaches the database, `localStorage`, or a
   session-keyed row.
2. The device-kept code path is DELETED, not merely unreferenced.
3. `/today` and `/library` gate with the destination preserved.
4. `/daily-bread`, `/series`, `/devotional/*` and Soul Audit stay open.
5. A pending intent completes after sign-in.
6. The gate does not ship until a live sign-in is verified against production.

## Outcomes log

- **2026-08-16 — the data half shipped.** Device-kept highlights removed
  (key + read/write/mutate helpers deleted); `/api/bookmarks` gated on all three
  methods; `/today` and `/library` gated with redirect-preserving destinations;
  `highlight` and `journal` intents added so a signed-out reach completes after
  auth. `save-state-auth-gate` reversed with its reasoning recorded.
- **Outstanding — the release gate.** A real end-to-end sign-in against
  production has NOT been run. Google sign-in is now live, which largely defuses
  the ~2-emails-per-hour mailer cap, but the verification still owes.
- **Outstanding — intent replay.** The intent is recorded and the modal opens;
  replaying the captured action automatically after the reader returns is not
  yet wired end to end.

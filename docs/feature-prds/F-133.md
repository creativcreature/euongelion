## Shipped

### 46 · Filter search results by kind

The corpus reaching this overlay is more varied than the surface admitted:
series, devotionals and the reader's own marginalia all arrive in one stream.
[Matter](https://mobbin.com/screens/1f3f1157-0870-45e7-afff-0c1fc6633bae) groups
by content type; this filters to one at a time.

`ALL · SERIES · DEVOTIONALS · YOUR NOTES`, each carrying its live count, sitting
between the input and the first group so the reader sees what the corpus holds
before scrolling it. Verified with a real query: `ALL 10 · SERIES 2 ·
DEVOTIONALS 8 · YOUR NOTES 0`, and choosing SERIES collapsed the result set to
that group alone.

`all` is the default and resets on each open — the filter is an affordance,
never a gate. Counts use tabular figures so the row does not shimmer as the
query changes.

### 23 · Highlights grouped by series, with counts

[Blinkist](https://mobbin.com/screens/1eb6873a-771b-455d-9e37-7cd1f773cdf8)
lists "Atomic Habits — 1 highlight" rather than a flat stream, and the reason
shows up over time: a flat list stops being usable at roughly the point it
starts being valuable. Months of marginalia is exactly when a reader wants the
thing they marked in one particular series.

Two properties held deliberately:

- **Order is never rewritten.** Groups and rows both keep the incoming
  newest-first order, so grouping reorganises a reader's history without
  reordering it.
- **Nothing is dropped.** Anything whose series cannot be resolved falls into a
  final "Other readings" group rather than vanishing.

Group headings are sticky, so the series a reader is scrolling through stays
named.

## A build break, caught in verification

The first version imported `findSeriesForSlug` from `@/lib/today-devotional`.
That module also owns the Workers content fetch, so it drags `node:fs` and
`node:path` with it — and this rail is a **client** component. The build failed
outright:

```
Module build failed: UnhandledSchemeError:
Reading from "node:fs" is not handled by plugins
```

`type-check` and `lint` both passed; only the real build caught it. Replaced
with a local resolver over the `SERIES_DATA` this file already imports.

**Worth keeping:** a green `tsc` says nothing about whether a server-only module
just crossed into a client bundle. That is the second time this week a gate has
been green while the build was not.

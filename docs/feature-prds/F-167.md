# F-167: The player carries what real players carry

## Metadata

- Feature ID: F-167
- Category: Reading surfaces
- Owner: founder
- Status: shipped
- Decision: SA-122
- Surfaces: `src/components/audio/AudioDrawer.tsx`, `next.config.ts`

## Problem

Founder: "the reader needs to be based on real world readers, you have a lotta
missing features that are fairly standard for audio. players needs to be
reworked based on research from mobbin... dont half ass it."

Eight players were surveyed on Mobbin — Spotify Audiobooks, Apple Podcasts,
ElevenReader, Headway, Blinkist, Finimize, Patreon, The Atlantic. Full analysis
with citations: `docs/audio/PLAYER-GAP-ANALYSIS-2026-08-20.md`.

## What the research settled first

**The shape shipped in F-165 is what real products do.** Blinkist, The Atlantic,
SCMP and Speechify all dock a slim bar over the text and keep the full player
elsewhere. So this is not a reversal of option A; the finding is that our _full_
player was under-furnished.

## What changed

**Volume.** Apple Podcasts and ElevenReader both carry one, and a desktop
listener had no in-page volume at all. Hidden at `pointer: coarse` — iOS Safari
ignores the volume property outright, and a control that moves without changing
anything is worse than none.

**Share.** The most-carried feature we lacked, in four of the eight. System
share sheet where there is one, clipboard where there is not; the button says
"Link copied" so the fallback is not silent.

## The defect the research turned up

**The CSP had no `media-src`.** Confirmed on the live site by listening for
`securitypolicyviolation`: loading narration from a blob URL fires
`{ directive: 'media-src', blockedURI: 'blob', disposition: 'enforce' }`. With no
directive, media falls back to `default-src 'self'`, which does not cover
`blob:` — so the offline path, where the service worker synthesises 206
responses out of cached bytes, was blocked outright.

CHANGELOG already claimed "`media-src` now names the R2 host". It did not. The
existing CSP tests could never have caught that: `security.test.ts` asserts
against a hardcoded COPY of the header, so it passes no matter what
`next.config.ts` says. The new test reads the real config.

This also corrects an error of mine from earlier tonight. I reported that the
browser could not decode AAC, on the evidence of a blob that failed instantly.
The blob was blocked by this CSP. The codec claim was wrong and is withdrawn.

## The second defect: half the sidebar had no CSS

Caught by opening the deployed player and reading computed styles rather than
trusting the tests. Five classes — `lsn-seek`, `lsn-seek-label`, `lsn-times`,
`lsn-extras`, `lsn-chip` — appeared in the markup and in **no rule**. The player
rendered `0:0011:18 left` and `1x speedSleep timerChaptersShare`: the times and
the chips jammed together, every element still `display: block`.

Every one of those classes is a control added in SA-119 the night before, to
make the sidebar "the full player". The markup landed; the CSS did not. So the
founder's "you have a lotta missing features... dont half ass it" was more
literally true than intended — the features were there and looked broken.

**Why nothing caught it.** Unit tests query by role and accessible name, and an
unstyled button is perfectly findable — all 39 passed against this. Type-check
and lint do not look at whether a `className` has a matching rule.
`audio-drawer-styles.test.ts` now parses the component, splits it at the
styled-jsx block, and fails if any `lsn-` class in the markup has no rule. RED
listed exactly those five.

## Contract

### Desktop

- The sidebar carries a volume slider that drives the shared element.
- The sidebar carries Share.
- The CSP names `media-src 'self' blob: data:`.

### Mobile

- Volume is hidden at `pointer: coarse`, deliberately.
- Share uses the system sheet.

## Acceptance

- [x] Every `lsn-` class the sidebar renders has a rule, enforced by a test.
- [x] Volume control exists and sets the element's volume.
- [x] Share uses `navigator.share` when present.
- [x] Share falls back to the clipboard, visibly.
- [x] The CSP names `media-src`, asserted against the real config.
- [x] Written test-first; RED was three missing controls and a CSP with no
      `media-src` directive at all.
- [x] Type-check clean; audio suite green at 39.
- [x] **The cause of the stall is isolated, and it is not the product.** With
      the service worker unregistered, caches cleared and zero CSP violations, a
      `blob:` URL built from 6,187,773 already-fetched bytes times out at ten
      seconds — exactly as the same-origin URL does. A blob touches no network,
      so network, byte ranges, the R2 route, the service worker and CSP are
      ruled out together: the media element in this browser never leaves
      `readyState 0` for anything. Not a codec refusal either — that claim
      rested on the CSP-blocked blob and is withdrawn.
- [ ] **Playback therefore remains unverified on a real device.** Everything
      measurable says the delivery path is correct — valid faststart AAC,
      correct 206s, correct bytes — but no session can watch it play. Thirty
      seconds on a phone closes it. Mobile layout is unverifiable here for a
      related reason: `innerWidth` stays 1706 whatever the window is resized
      to.

## Not built, and why

- **Cover art** (7 of 8 players lead with it) and **section-level read-along**
  (ElevenReader, Speechify, Headway, Blinkist) are real builds against the
  reading surface signed off hours earlier. Word-level read-along needs per-word
  timings the render pipeline does not emit.
- **Naming the narrator** (ElevenReader "Oliver Silk", Speechify "MrBeast") is
  evidence for the founder's pending ruling on disclosing synthesised
  narration. His call, so it stays a recommendation.

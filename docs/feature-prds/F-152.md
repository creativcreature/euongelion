## Problem

`docs/DEVO-PIPELINE-HANDOFF-SPEC.md` Part I puts the manifest schema and its
validator first, before any stage is built. Neither existed.

The manifest at `content/pipeline/<slug>.pipeline.json` is what every stage reads
and writes. Resume, partial rerun, `--auto` mode and the evidence report are the
same mechanism — a stage advancing a state machine — so a malformed manifest is
not cosmetic. It is a pipeline that cannot be trusted to know what it has already
done.

**But the firewall is why this ships first.** `last30days` returns Reddit posts,
X threads and YouTube comments. That is excellent evidence about what readers
**ask** and the **words they use**, and no evidence whatsoever about God,
Scripture or history.

devo-go's regime — scripture pulled corpus-verbatim, every quote cited from
primary texts, every story primary-source verified with the rejection documented
— is the product's advantage in a category drowning in unverified AI output. One
Reddit anecdote laundered into a devotional through the discovery channel would
cost more than the entire discovery stage gains.

Spec Part E states the rule. Convention cannot hold it across sessions and
agents; it has to be mechanical.

## Fix

`scripts/validate-pipeline.mjs`, wired as `verify:pipeline` in the pre-commit
chain. It no-ops cleanly while no manifests exist, so it can land before the
stages do.

**Schema** — `schema`, `slug`, `thematic`, `mode`, per-stage `state` against a
closed set, and `rulings.sa`/`rulings.prd` required so a run cannot be
unattributable. The filename must match the slug, because resume finds manifests
by filename.

**Firewall** — no phrase in `discovery.audience_language` may appear verbatim in
any `public/devotionals/<slug>-*` body or in `content/source-packs/<slug>.md`.
Matching normalises punctuation and casing, so reformatting is not an escape
hatch. Phrases under four words are ignored: those collide by coincidence, not by
lifting.

A violation exits **2**, distinct from a schema error's **1**, so a caller can
tell "malformed" from "contaminated" — they need different humans.

## Verified

`__tests__/pipeline-manifest-firewall.test.ts` — 9 tests against the real script:

- a well-formed manifest passes
- unknown stage state, slug/filename mismatch, and missing rulings each fail
- **a phrase reaching a devotional body BLOCKS**, and prints the phrase and file
- the violation exit code is distinguishable from a schema error
- the same phrase passes when it has _not_ been lifted
- short phrases are ignored
- **punctuation and casing changes still match**

## Deliberately not built

The `devo-run` skill skeleton with its eight gates. Phase 0 in the spec covers
both; the validator is the half that protects the corpus and can land safely
alone, and the orchestrator is better authored alongside the first real stage.

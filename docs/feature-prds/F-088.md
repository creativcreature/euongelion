# F-088: Reader declutter — nothing above the devotional title

## Metadata

- Feature ID: F-088
- Category: Reading experience
- Owner: founder
- Status: in progress (2026-08-14)
- Decision: SA-037
- Surfaces: `/devotional/[slug]`

## Problem

Founder, 2026-08-14, on `he-cannot-deny-himself-day-5` ("Between the Pieces"):

> Nothing above the individual devotional title should appear on page … all
> information above where this first appears on page is completely bogging
> down the reading experience.

Measured against the running site before the change, at 1280×900 the title
**never appeared on the first screen at all**. Six blocks preceded it:

| Block                                             | Location                                      |
| ------------------------------------------------- | --------------------------------------------- |
| Masthead + pronunciation + nav                    | `EuangelionShellHeader` (site-wide, retained) |
| `Breadcrumbs`                                     | `DevotionalPageClient:465`                    |
| Substack cover banner                             | `DevotionalPageClient:490`                    |
| Action row (BACK TO SERIES / SHARE / SUBSTACK)    | `DevotionalPageClient:512`                    |
| `DevotionalActions` (START / SAVE)                | `DevotionalPageClient:547`                    |
| `DevotionalFolio` — carrying `ChurchYearOverline` | `DevotionalPageClient:752`                    |

The devotional page measured 25,118px on desktop and 33,100px on mobile.

## Scope

This is a **removal and reorder**, explicitly not a restyle. No new stylesheet,
no new type scale, no new colour. An earlier attempt introduced a bespoke
reader layout and was rejected by the founder — the site's existing components,
classes and type carry the change.

### Removed

Breadcrumbs (the last crumb repeated the title), the Substack cover banner
(imported article headers are to be replaced by library artwork — separate
work), and `DevotionalFolio`, which was the vehicle carrying
`ChurchYearOverline` onto every devotional. Per founder, the church-year line
belongs on the home page, unobtrusively — that placement is **not yet done**.

### Moved, not removed

The action row and `DevotionalActions` now sit after the reading. Founder:
"the links and such are needed, but the current implementation is very clunky
and buries the content."

### Reordered

`DevotionalHeadline` rendered the scripture line _above_ the title. Order is
now title → dek → scripture. On mobile the art stacked above the title because
the art div precedes the text in DOM order; a single `order: 2` in the existing
`@media (max-width: 900px)` block places it after, and the dividing rule moves
to the art's top edge to match.

### Added

The day's teaser renders as the standfirst via `.devotional-headline-dek` — a
class present in `globals.css` since the 2026-05-13 audit that no prop had ever
fed. Founder asked for "a short summary of the reading (that includes pointing
to the scripture)"; the dek is the summary and `scriptureReference` the pointer.

### Also fixed

`NarrationPlayer`'s control row was a non-wrapping flex row of five controls.
At 375px "LISTEN" and "CHAPTERS" broke mid-word and the buttons overlapped. The
row wraps now and each label stays on one line.

## Acceptance criteria

1. No element other than the site header renders above `h1.devotional-headline-title`,
   at 375px and 1280px. Verified by DOM probe, not inspection.
2. Title, teaser and scripture reference all render, in that order.
3. Church-year furniture appears nowhere in a devotional reading.
4. Back-to-series, share, start and save all remain reachable, after the reading.
5. Narration controls at 375px: no mid-word wrapping, no overlap, ≥44px targets.
6. No horizontal scroll at either width.

## Known gaps

- Church-year line is removed but **not yet placed on the home page**.
- `/daily-bread`'s `CuratedActiveView` keeps its own `ChurchYearCard` and its
  OPEN FULL READER step. Untouched here.
- The fixed reader-theme trigger (bottom-left, `z-200`) can overlay the in-page
  narration controls. `:root[data-narration-bar='true']` already lifts it clear
  of the _mini bar_, but not of the in-page player panel.
- Series-level save and the reader consolidation remain unstarted.

## Verification

- `npm run type-check` clean
- `npx eslint` clean on all changed files
- DOM probe at 375px: title at y=172, art at y=403; elements above the title are
  masthead-only
- Narration row at 375px: wraps, every control ≥44×44

## Follow-ups shipped same day

### Day quick-links

Founder, after reviewing the live change: _"there should be links to all the
days of the devotional at the top to act like small quick links."_ Rendered
under the headline — above it would contradict SA-037 — with the current day
marked. Gated to series of <=31 days; longer plans keep the existing day-nav
pill.

### Highlights failing silently

Founder: _"the highlight feature doesnt work. The text doesnt highlight
visibly. I can choose a color and everything, but the actual color never
renders."_

Diagnosed before changing anything. The styling is **not** the fault: injecting
`<mark class="reader-highlight reader-highlight--yellow">` into the live page
computes `background: rgba(246, 223, 128, 0.54)`. The mark simply never reached
the DOM, because `applyHighlightMark` runs only after `response.ok` and every
non-auth failure fell through a bare `return` — no mark, no message. Failures
are now reported on the toolbar button.

For a signed-out reader the endpoint returns 401 `AUTH_REQUIRED_SAVE_STATE`.
That is SA-018 operating as locked, not a bug, and the gate was left alone.

### Highlighting without an account (SA-038)

Founder, once told the 401 was the locked gate: _"I was signed in, but should
work regardless, just not save to an account without an account."_

So the mark is now painted from the selection at press time and never waits on
the network. An account decides whether a highlight is **kept**, not whether it
appears. Signed-out readers see the highlight and are told "Sign in to keep
this" instead of being thrown to a sign-in screen mid-reading.

Three silent returns in this path were removed: a missing range (which the
scroll handler causes in ordinary use), a non-auth save error, and a mark that
wrapped an empty range and rendered invisibly.

Verified end-to-end in a browser, signed out: API returned 401 and the mark
still painted at `rgba(246, 223, 128, 0.54)`.

### Closing the original four complaints

- **Church year** removed from every devotional and placed on the home page as
  one quiet line under the masthead. It had been left with nowhere to live.
- **Daily Bread's "OPEN FULL READER"** removed. The reader is already reading
  the devotional; offering the real one implied this was a lesser copy. Its
  folio strip (which carried `ChurchYearOverline` here too) is gone and its
  headline now matches `/devotional/[slug]`.
- **Audio Edition added to Daily Bread**, the one reading surface that lacked
  it — which is why audio looked like a feature of the "other" reader.
- All three reading surfaces now behave identically. `DailyBreadView` (the
  soul-audit plan path) already had audio and none of the furniture.

**Not closed:** saving a _series_ rather than individual devotionals. It needs
a `saved_series` table, and prod DDL requires founder-named approval — see
Known gaps.

### Series-level save (SA-039)

Founder: _"User should save a devotional series, not individual devotional."_

`SAVE SERIES` stores the series slug. No migration was needed: `/api/bookmarks`
validates slug _safety_, not that a slug names a devotional, so a series slug
stores in the existing `session_bookmarks` shape. That deliberately avoids
adding a fourth unapplied migration behind the three billing ones still pending
before `GENERATION_GATE_LIVE`, and avoids prod DDL, which needs founder-named
approval.

Existing per-day rows roll up rather than being rewritten — a saved day counts
as its series being saved. That is the auto-migration, achieved by reading
instead of mutating anyone's library. Nothing is deleted and no backfill runs.
Unsaving clears the series row and every legacy day row for it.

The library shelves by series: a saved series links to `/series/<slug>` (since
`/devotional/<series-slug>` is a 404) and reads "Whole series · N days".

Pinned by `__tests__/series-save.test.ts` (11 cases), including the
`identity-crisis` → `identity` rename.

### Anonymous highlights kept on device (SA-039)

A highlight made without an account is written to `localStorage` and restored
on load, deduped against server rows so a since-signed-in reader never sees the
same passage marked twice. Still not written to the database — SA-018's line on
persistence-to-an-account holds. Verified: highlight, reload, one mark survives.

### Closing tweaks

**Reader-theme button no longer covers the audio controls.** It is fixed
bottom-left at `z-200`, so at phone widths it landed on the −15 control
whenever the in-page Audio Edition panel was on screen. `NarrationMiniBar`
already solved the same collision with `data-narration-bar`; the panel now
performs the same handshake via `data-narration-panel`, reusing the
`panelVisible` observer that already existed. Mobile only — desktop has room
for both. Verified at 375px: panel on screen → opacity 0 / pointer-events none;
panel scrolled away → the control returns.

**Substack cover replacement: closed as unnecessary, not skipped.** The founder
asked for the 93 imported Substack headers to be regenerated as riso plates via
Higgsfield. Removing the cover banner turned out to be the last surface that
rendered them: all 26 series carry a `heroImage`, so the `series-hero.ts`
Substack fallback never fires, and three live pages sampled across
Substack-sourced devotionals return zero Substack image references. Regenerating
them would have cost roughly 660 Higgsfield credits to replace pictures that no
longer appear anywhere. The legacy fallback branch is left in place as a safety
net for any future series shipped without art.

## Platform contracts

### Desktop

The headline keeps its existing 2fr/1fr grid — plate left, text right — so the
title, dek and scripture pointer all land on the first screen at 1280x900
alongside the artwork, and the Audio Edition panel sits directly beneath. The
site masthead is retained above the reading; it is site chrome, not page
furniture, and removing it was raised and not adopted. Measured: title enters
the viewport where previously it did not appear on the first screen at all.

### Mobile

At <=900px the headline collapses to one column. The art div precedes the text
in DOM order, so `order: 2` places the plate after the title; the dividing rule
moves from the art's bottom edge to its top. Measured at 375px: title y=172,
plate y=403, no horizontal scroll. Narration controls wrap rather than
compress, every control >=44x44, and no label breaks mid-word.

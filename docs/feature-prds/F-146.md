## Problem

Founder, 2026-08-19: a new devotional series produced weekly "in the same
way per the devo-go guidelines," on the Claude subscription just after the
Wednesday 5am quota reset — full quality (ElevenLabs voice, /imagen art),
thematic derived from last-30-days research, building on the prior week
without referencing it, with a manual override for the founder's own
thematic, auto-creating when no override exists.

## Solution

A local launchd job (Wednesdays 5:20am Eastern — local-time, DST-free)
runs `scripts/devo-weekly/orchestrate.sh`:

1. **Thematic**: `content/next-series-thematic.md` override when the founder
   wrote one (archived to docs/run/, file reset); otherwise headless
   last-30-days discovery over faith/culture conversation + the prior
   week's series thread → one topical, scripture-anchorable thematic
   (the news is the doorway, never the content).
2. **The build**: headless Claude Code (subscription-billed) executes the
   devo-go skill end to end on a `series/auto-YYYY-MM-DD` branch —
   research-verified writing, /imagen imagery through Codex (built-in tool,
   anchors, assembled prompts), ElevenLabs founder-voice narration —
   governed by `scripts/devo-weekly/STANDING-BRIEF.md`, the founder's
   standing answers to devo-go's Required Inputs (editable).
3. **The gate stands**: the run STOPS after the reading-gate artifact and a
   pushed branch, then notifies. SA-029's founder reading gate is a
   standing ruling; automation does not override it. The explicit switch —
   `touch scripts/devo-weekly/AUTO_PUBLISH` — flips to full-auto
   merge-and-deploy, the founder's call alone.

Why local, not CI: the 13GB reference library, Codex CLI auth, and the
narration toolchain exist only on this Mac. If the Mac sleeps through
5:20, launchd runs the job on next wake.

## Solution

Flow leads the toggles and is the default view. Rose is removed entirely — view,
geometry, tests and CSS. It was beautiful on a desktop and never survived a
phone.

The reference's own instruction to its reader is *"SCROLL / DRAG TO INTERACT W/
THE ARTBOARD"* — so what is borrowed is a **behaviour**, not a look. The
palette, plates and typography stay Euangelion's.

**Tile size encodes length.** A 60+ day reading takes a 2×2, a 7+ day a 2×1,
everything else a single cell, packed leftmost-lowest so the board has no holes.
Deterministic from the sort order: change the sort and the board rearranges to
match. Never random.

## The board is a CSS grid, and that is the point

The first build positioned tiles absolutely on a **measured** canvas, and the
measurement was the bug:

- an un-laid-out frame reports `clientWidth === 0`
- `??` kept the `0`, because `0` is a number
- the board froze at its default column count, leaving a block of dead space on
  the right — exactly the "awkward spaces" called out in the same message

Rewritten as a grid at `width: 100%`, the board **fills its frame by
construction** and no measurement can be wrong. Only the column *count* comes
from the viewport: 2 on a phone, rising to 5 on a wide desktop, because past
five the plates stop being readable.

## Mobile Flow is a native scroller, not a dragged board

A drag-panned board is a desktop idea. On a phone it fights everything the
platform already does well — momentum, rubber-banding — and, worse, it **traps
the page**: a finger inside the frame pans the board to its end and then has
nowhere to go, leaving the reader stuck mid-page.

So under 900px the frame becomes an ordinary scroll container with the board
static inside it. Same tiles, same packing, same sizes; the motion belongs to
the operating system, which is the motion a phone user expects.

## Contract

- Flow plates load **eager**. Chrome does not fire its lazy loader for children
  of a transformed container — the same trap the rose window hit — so every tile
  would otherwise sit as an empty plate ground forever.
- Every tile is a real `<Link>`; focusing one pans it into view on desktop.
- Momentum, blur and drag are all disabled under `prefers-reduced-motion`.
- A drag that ends on a tile does not open it.

## Platform Contracts

### Desktop

- Drag, wheel and trackpad pan the board; release throws it with friction.
- Blur scales with speed, capped at 5px, and settles to zero at rest.
- Wheel releases to the page at the board's vertical limits, so it never traps.

### Mobile

- Frame is `overflow-y: auto` with `overscroll-behavior: contain`; drag and
  wheel handlers bail out entirely.
- Two columns under 560px so a tile stays thumb-sized.
- The "drag the board" hint is hidden, because drag is not the gesture.

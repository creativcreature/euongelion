# F-168: Mobile images survive one bad network moment

## Metadata

- Feature ID: F-168
- Category: Homepage
- Owner: founder
- Status: shipped
- Decision: SA-123
- Surfaces: `public/sw.js`, `src/app/page.tsx`

## Problem

Founder, 2026-08-24: "The mobile version of the homepage doesnt load the
images." Production probes could not reproduce it — real Chrome and real
WebKit at 375px both painted the hero, the featured art, the step plates,
and the series-rail thumbnails, and all 21 hero variant files returned 200.
The failure mode lives on the device:

1. The service worker's image handler was cache-first with a catch that
   fabricated an EMPTY `404` response on any failed fetch. An installed PWA
   keeps the same page alive for days, so one bad network moment (a dead
   spot, Low Data Mode, iOS suspending the app mid-fetch) painted every
   in-flight image permanently blank until the page itself reloaded.
2. The homepage's most prominent image — the featured devotional art, an
   LCP candidate — was `loading="lazy"`, deferring the one image a phone
   reader is guaranteed to want.

## Solution

- The image handler retries a failed fetch once, then gives up with
  `Response.error()` — a REAL network error, never a fabricated success-
  shaped 404. Successful responses are cached exactly as before.
- The featured devotional `<Image>` gains `priority` (preloaded, eager,
  high fetchpriority).
- SW pair bumped to v151 so every installed client re-registers and picks
  up the hardened worker.

## Platform Contracts

### Desktop

- Behavior identical to before on a healthy network: cache-first images,
  priority featured art. No layout change.

### Mobile

- A transient network failure during image fetch no longer blanks the
  image permanently in a long-lived PWA page; the retry covers blips and a
  real network error lets the browser surface a genuine broken state.
- The featured art loads eagerly at phone widths.

## Acceptance

- `__tests__/mobile-image-reliability-contract.test.ts` (watched red
  first) pins: no fabricated empty 404 anywhere in sw.js; the image branch
  retries once and fails with `Response.error()`; the featured Image
  carries `priority`.
- Full gates green; live homepage HTML carries the priority preload; live
  sw.js serves v151.

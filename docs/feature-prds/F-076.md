## Problem

Custom generation (the Soul Audit's bespoke plan composition) ran anonymous
and unmetered — every select spent real model dollars with no account, no
grant, no entitlement. SA-026 gates bespoke generation behind a verified
account (1 free generation each, then subscription per SA-027) while keeping
the audit, option review, and all curated reading anonymous and free forever.
Separately, the status poll had no ownership scoping: any holder of a leaked
jobId could poll progress and trigger generation kicks (§12.3 IDOR).

## User Expectation

- I can take the Soul Audit and see my 3 paths without an account, ever.
- Composing my custom plan asks me to sign in once; my first edition is free.
- After that, one clear paywall moment — never mid-reading, never a surprise.
- Nobody else can watch or drive my plan's generation.

## 10/10 Definition

- `/api/soul-audit/select` (new plans only): 401 `SIGN_IN_REQUIRED` when
  anonymous, 402 `GENERATION_ENTITLEMENT_REQUIRED` when unentitled — checked
  BEFORE any plan/job creation or model spend. Idempotent re-selects never
  gated or double-charged.
- Free grant consumed atomically (`WHERE free_generation_used_at IS NULL`);
  reserved only after all pre-checks pass; released on any creation failure.
- Subscribers: monthly allowance (env `SUBSCRIPTION_MONTHLY_GENERATION_ALLOWANCE`,
  default 6, ≤0 = unlimited) counted honestly from plan instances.
- Status route scoped to owning session or its signed-in user; others 404.
- `GENERATION_GATE_LIVE` ships the gate together with the paywall UI (no
  partial launch: gating without a way to pay never reaches production).

## Device Contracts

### Desktop

- Backend gate returns typed codes (`SIGN_IN_REQUIRED`,
  `GENERATION_ENTITLEMENT_REQUIRED` + reason) that the desktop paywall
  spread (F-077+) translates into the approved pattern-decision screens.

### Mobile

- Same typed codes drive the mobile full-height paywall sheet; no
  device-specific gate behavior server-side.

## User Expectation

The founder reads on the site and wants to listen on the site, while working.
The shipped Audio Edition failed him two independent ways, and only one of them
was about the voice.

1. **It sounded robotic.** It was the browser's Web Speech API (F-030) — a
   screen reader. No voice-ranking heuristic fixes that; it is the wrong class
   of engine.
2. **It skipped roughly a third of every devotional.** Measured across 521
   devotionals, `moduleText()` in `src/lib/audio/segments.ts` spoke a median
   **70.7%** of each entry's distinct prose, because it read a fixed field list
   and the corpus stores prose in fields that list never named. About
   **252,000 words** catalog-wide were never read aloud — every `profile`
   module, `insight.historicalContext`, `vocab.usageNote`,
   `bridge.newTestamentEcho`, `story.connectionToTheme`, and the
   `comprehension` question (the answer was read without its question). Word
   studies were read as bare definitions with no headword: "safety, security,
   certainty…" with no indication the word was _asphaleia_.
3. **It could not play in the background at all.** `speechSynthesis` is not a
   media element, so the Media Session API has nothing to attach to. No lock
   screen, no headphone controls, and iOS stops it when the screen sleeps.
   Listening while working was impossible by construction, whatever the voice.

## 10/10 Definition

- Every devotional is read **complete and verbatim** — shaping may alter
  punctuation and chunk boundaries, never wording.
- Narration plays through a real `<audio>` element so it survives a
  backgrounded tab, drives the lock screen, and can be cached offline.
- **One voice across the entire catalog**, mechanically enforced.
- Pace inside the audiobook narration band (150–170 wpm).
- Devotionals without a rendered track degrade to the Web Speech reader rather
  than losing audio entirely.

## What Shipped

**Reading contract** (`src/lib/audio/segments.ts`): explicit ordered field list
per module type; mirrored fields deduped (`teaching.content` ==
`teaching.body`, byte-identical in 1,410 of 1,422 modules — reading both would
have doubled the text); a catch-all sweep so a field appearing in only a few
modules can never go silent again; vocab headwords restored; Hebrew/Greek
glyphs stripped with the transliteration retained; scripture references
expanded to spoken English including compound forms ("Job 1:1, 20-22; 2:10");
Roman numerals in citations expanded after a cue word only, so the pronoun "I"
is untouched; navigation modules (video, cta, resource, images) no longer read.

Measured over 521 devotionals: **648,094 → 888,899 words spoken, +37.2%**,
median **1.37×**, and **zero devotionals regressed** (minimum 1.03×).

**Narration engine**: Kokoro-82M, voice `am_michael`, run locally through
Voicebox. Not a clone — see SA-035 for why the founder-voice clone path was
abandoned on evidence. Renders whole segments (a 352-word passage in 12s), so
prosody arcs across a paragraph instead of resetting every 40 words.

**Player** (`src/components/NarrationPlayer.tsx`, `src/lib/audio/tracks.ts`):
real `<audio>` element with Media Session metadata and handlers, scrub, ±15s,
speed 0.8–1.5×, and resume-where-you-stopped. `AudioPlayer` selects it whenever
a track exists and otherwise renders the unchanged Web Speech fallback.

## Delivery Contract (caching + seeking)

Verified in the Workers preview runtime: `/audio/*.m4a` was served with
`Cache-Control: public, max-age=0, must-revalidate` and no `Accept-Ranges`, so
an 8 MB / 22-minute track was re-fetched on every visit.

The seeking consequence matters more than the bandwidth. Cloudflare strips the
`Range` header before invoking the Worker and slices byte ranges out of **its
own cached copy** of the full response, so range requests — and therefore cheap
scrubbing — only work when that response is cacheable. `max-age=0` defeated it.

`public/_headers` now serves `/audio/*` immutable for a year. Immutable is only
safe if a re-render changes the URL, so `getNarrationTrack()` stamps
`?v=<encoded byte size>` onto `src`; re-rendering a day after a pronunciation
fix therefore invalidates cleanly instead of pinning a stale reading in
browsers for a year.

### Manifest is a build input, not a served asset

The `/audio/*` immutable rule swept up `manifest.json`, an index rewritten by
every render, so production served a year-cached track list. Adding a path
exception to `_headers` does NOT fix this: Cloudflare appends the second rule
rather than overriding, producing
`public,max-age=31536000,immutable, public,max-age=300,must-revalidate` — two
contradictory directives on one header. `_headers` has no negation syntax.

The manifest now lives at `src/data/audio-manifest.json`, imported at build
time and never served. `/audio/*` therefore contains only `.m4a` files, and the
immutable rule is unambiguously correct for everything it matches.

## The Reading Rule (mini bar)

Control has to survive the reader scrolling past the Audio Edition panel — but
a persistent media widget is exactly what SA-034's founder direction removed
from that panel, which had the page opening like app chrome. Resolved by
building a bookmark ribbon rather than a player:

- **The bar has no top border; its top edge IS the progress line.** A cobalt
  rule fills left to right across the full viewport, reading as a place-marker
  in a book, and doubles as the seek control — the quietest element is also the
  largest target.
- **It is earned, never default.** It appears only after the reader presses
  play AND scrolls the panel out of view, and retires the moment the panel
  returns. A reader who never presses play never meets a media widget.
- **One `<audio>`, two UIs.** The bar portals out of `NarrationPlayer`, so both
  surfaces drive the same element and the same state. Two elements would
  double-play.
- **Content sits on the reader's grid**, not the viewport: the play control
  lands on the exact vertical of the "AUDIO EDITION" label it replaces
  (verified delta 0px). Near-alignment reads worse than none, so the padding
  reproduces the shell's container chain instead of approximating it, and stays
  in rem because the reader's text-size control moves the root font size.

Three collisions found by measuring rather than by eye, all fixed:

| Problem                                              | Cause                                                                                | Fix                                                                 |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| Theme button sat on the play control                 | `.reader-theme-trigger` is fixed bottom-left at z-200                                | `data-narration-bar` on the root lifts it and the chat button clear |
| Progress rule rendered flat                          | `--pct` was set on the `<input>`; the fill span is its SIBLING and inherited nothing | variable moved to the label                                         |
| 6px sliver of scrolling text between bar and tab bar | offset borrowed from the body's bottom padding, which has slack                      | derived from the tab bar's own box (`0.68rem + 44px`)               |

Transport: play/pause, back 15s (all breakpoints), forward 15s (desktop only —
listening while working, the recurring need is "say that again", not skipping
ahead), remaining time, and the title as a button that returns to the panel.

## Deploy Contract (service worker)

A deploy is not visible until the service worker version moves. Reading routes
use `cacheFirstWithUpdate` and `/_next/static/` is served from cache when
present, so a returning reader receives the previous build's HTML _and_ the old
chunk hashes it references — the entire prior app. The narration player and the
reading rule both deployed correctly and were invisible to anyone who had
opened the site before.

`public/sw.js` states the rule at the top of the file: keep `CACHE_NAME` in
sync with `SW_VERSION` in `src/components/ServiceWorkerRegistration.tsx`. On a
mismatch the client unregisters every worker, deletes every `euangelion-*`
cache, and re-registers. Four deploys of new client code went out without
bumping either; both are now `v52`.

**Any future change to client code under this feature must bump that pair.**
Self-healing is one load behind: the visit that fetches the new `sw.js` may
still paint the cached page, and the load after it is clean.

## Chapters

Each devotional heading is a navigable point in the recording, reachable from a
pull-up sheet, with the section being read marked in the page.

**Timestamps are measured, never estimated.** Word-count estimates drift tens of
seconds over a 20-minute track and land mid-sentence. Every render already
writes a per-devotional manifest of measured segment durations;
`spec/build_chapters.py` zips those against a fresh extraction (which knows
module indices) and replicates the stitcher's pause grammar exactly — omitting
those gaps would drift about half a second per segment, roughly 20 seconds by
the end of a long reading. Verified by decoding the shipped audio and
transcribing at three marks: `Closing Prayer` at 21:21 opens "Father, you said
your own name out loud on a mountain".

Extraction is deterministic — re-running it reproduces the rendered segment
list text-for-text, checked across the corpus — so the join is safe. Any
devotional whose re-extraction does NOT match is skipped and reported rather
than emitted with wrong timestamps. That guard fired for
`he-cannot-deny-himself-day-1`, which predates later extractor changes and
needs a re-render.

Every rendered devotional has chapters: median 10, max 24, zero skipped.

The guard earned its place immediately. It refused `he-cannot-deny-himself-day-1`,
which turned out to have audio predating the Roman-numeral fix — the file said
"chapter VIII" where the page says "chapter eight", the exact ambiguity that fix
removes. Re-rendered and confirmed by decoding the shipped audio at 14:50, where
the numeral is now spoken as a word. A builder that guessed instead of failing
would have shipped both wrong marks and a stale reading.

**A sheet, not a list.** SA-034 removed the section scrubber because printing
every section above the article read as a table of contents and spoiled the
headings. That objection is to a list you cannot avoid seeing; a sheet is
opened deliberately, so the page still opens as an editorial. Bottom-anchored
at every width — a right-hand drawer was the reflex on desktop, but the ask was
a pull-up, and the sheet should rise from the transport it belongs to.

**Selecting a chapter moves both.** The ask was to "quickly scroll to the
section I want as it relates to the audio player", so a chapter is a position
in the reading and the recording alike: choosing one seeks the audio and brings
the page to the same section, never leaving the eye and the ear in different
places.

**The on-page marker is cheap by construction.** The article containing the
current chapter carries `data-narrating`, written only when the reading crosses
into a new section — roughly once a minute — never per frame. One `getElementById`
and one attribute toggle; no scroll listeners, no observers. It renders as a
gutter rule in the same cobalt as the transport and the sheet, so "where you
are" reads identically in all three places.

## Platform Contracts

### Desktop

- The Audio Edition panel sits below the folio and headline (unchanged from
  SA-034 founder direction). Where a track exists it renders the pre-rendered
  transport — play/pause, scrub, ±15s, speed, elapsed/total — instead of the
  section-stepping Web Speech control.
- Playback continues when the tab is backgrounded, and OS media keys drive it.

### Mobile

- 375px: transport controls stay ≥44px touch targets and wrap without
  horizontal overflow; the seek slider spans the panel width.
- Lock-screen controls show title, "Euangelion", and the app icon, and the
  play/pause/seek handlers drive the same element.
- Playback survives screen sleep — the specific failure of the Web Speech
  reader, which iOS halts because `speechSynthesis` is not media.

## Known Limits

**Word-study pronunciation cannot be verified automatically.** QA transcribes
each render with Whisper and diffs it against the source, but Whisper was not
trained on these transliterations and mangles them regardless of what the voice
does (`eleos` returns as "ilios"). The gauge is invalid for exactly these
terms, so they are the one part of the narration needing a human ear.

Measured and recorded so it is not rediscovered: the `pronunciation` field
already in the devotionals is **not** a drop-in replacement — the engine reads
its hyphens as breaks and the result is worse (`KHEH-sed` → "k-sad",
`as-FAH-lay-ah` → "as a phleia"), while raw `chesed` is already correct.
Overrides therefore live in `spec/pronunciation-overrides.json` and use
space-separated syllables. Overrides change only what is sent to the engine;
the devotional text is untouched, so the reading stays verbatim.

**Short devotionals pace slower** — 135–139 wpm against 162 for long ones,
because they have more, shorter segments and the fixed inter-section pauses
take a larger share. Inside audiobook range, but not uniform.

## Risks

**Storage.** The full catalog is ~1.9 GB across 521 files. Per-file (25 MiB)
and file-count (20,000) Workers limits are both satisfied, but 1.9 GB in git is
not acceptable. R2 is the correct home and is **not currently enabled on the
account** (API returns 403, "Please enable R2 through the Cloudflare
Dashboard"). Until it is, only the curated-series audio should be committed;
the `bible-365` bulk (365 files, ~1.4 GB) must wait.

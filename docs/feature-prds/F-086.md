## User Expectation

The founder reads on the site and wants to listen on the site, while working.
The shipped Audio Edition failed him two independent ways, and only one of them
was about the voice.

1. **It sounded robotic.** It was the browser's Web Speech API (F-030) — a
   screen reader. No voice-ranking heuristic fixes that; it is the wrong class
   of engine.
2. **It skipped roughly a third of every devotional.** Measured across 521
   devotionals, `moduleText()` in `src/lib/audio/segments.ts` spoke a median
   **70.7%** of each entry's distinct prose, because it read a fixed field list
   and the corpus stores prose in fields that list never named. About
   **252,000 words** catalog-wide were never read aloud — every `profile`
   module, `insight.historicalContext`, `vocab.usageNote`,
   `bridge.newTestamentEcho`, `story.connectionToTheme`, and the
   `comprehension` question (the answer was read without its question). Word
   studies were read as bare definitions with no headword: "safety, security,
   certainty…" with no indication the word was _asphaleia_.
3. **It could not play in the background at all.** `speechSynthesis` is not a
   media element, so the Media Session API has nothing to attach to. No lock
   screen, no headphone controls, and iOS stops it when the screen sleeps.
   Listening while working was impossible by construction, whatever the voice.

## 10/10 Definition

- Every devotional is read **complete and verbatim** — shaping may alter
  punctuation and chunk boundaries, never wording.
- Narration plays through a real `<audio>` element so it survives a
  backgrounded tab, drives the lock screen, and can be cached offline.
- **One voice across the entire catalog**, mechanically enforced.
- Pace inside the audiobook narration band (150–170 wpm).
- Devotionals without a rendered track degrade to the Web Speech reader rather
  than losing audio entirely.

## What Shipped

**Reading contract** (`src/lib/audio/segments.ts`): explicit ordered field list
per module type; mirrored fields deduped (`teaching.content` ==
`teaching.body`, byte-identical in 1,410 of 1,422 modules — reading both would
have doubled the text); a catch-all sweep so a field appearing in only a few
modules can never go silent again; vocab headwords restored; Hebrew/Greek
glyphs stripped with the transliteration retained; scripture references
expanded to spoken English including compound forms ("Job 1:1, 20-22; 2:10");
Roman numerals in citations expanded after a cue word only, so the pronoun "I"
is untouched; navigation modules (video, cta, resource, images) no longer read.

Measured over 521 devotionals: **648,094 → 888,899 words spoken, +37.2%**,
median **1.37×**, and **zero devotionals regressed** (minimum 1.03×).

**Narration engine**: Kokoro-82M, voice `am_michael`, run locally through
Voicebox. Not a clone — see SA-035 for why the founder-voice clone path was
abandoned on evidence. Renders whole segments (a 352-word passage in 12s), so
prosody arcs across a paragraph instead of resetting every 40 words.

**Player** (`src/components/NarrationPlayer.tsx`, `src/lib/audio/tracks.ts`):
real `<audio>` element with Media Session metadata and handlers, scrub, ±15s,
speed 0.8–1.5×, and resume-where-you-stopped. `AudioPlayer` selects it whenever
a track exists and otherwise renders the unchanged Web Speech fallback.

## Platform Contracts

### Desktop

- The Audio Edition panel sits below the folio and headline (unchanged from
  SA-034 founder direction). Where a track exists it renders the pre-rendered
  transport — play/pause, scrub, ±15s, speed, elapsed/total — instead of the
  section-stepping Web Speech control.
- Playback continues when the tab is backgrounded, and OS media keys drive it.

### Mobile

- 375px: transport controls stay ≥44px touch targets and wrap without
  horizontal overflow; the seek slider spans the panel width.
- Lock-screen controls show title, "Euangelion", and the app icon, and the
  play/pause/seek handlers drive the same element.
- Playback survives screen sleep — the specific failure of the Web Speech
  reader, which iOS halts because `speechSynthesis` is not media.

## Known Limits

**Word-study pronunciation cannot be verified automatically.** QA transcribes
each render with Whisper and diffs it against the source, but Whisper was not
trained on these transliterations and mangles them regardless of what the voice
does (`eleos` returns as "ilios"). The gauge is invalid for exactly these
terms, so they are the one part of the narration needing a human ear.

Measured and recorded so it is not rediscovered: the `pronunciation` field
already in the devotionals is **not** a drop-in replacement — the engine reads
its hyphens as breaks and the result is worse (`KHEH-sed` → "k-sad",
`as-FAH-lay-ah` → "as a phleia"), while raw `chesed` is already correct.
Overrides therefore live in `spec/pronunciation-overrides.json` and use
space-separated syllables. Overrides change only what is sent to the engine;
the devotional text is untouched, so the reading stays verbatim.

**Short devotionals pace slower** — 135–139 wpm against 162 for long ones,
because they have more, shorter segments and the fixed inter-section pauses
take a larger share. Inside audiobook range, but not uniform.

## Risks

**Storage.** The full catalog is ~1.9 GB across 521 files. Per-file (25 MiB)
and file-count (20,000) Workers limits are both satisfied, but 1.9 GB in git is
not acceptable. R2 is the correct home and is **not currently enabled on the
account** (API returns 403, "Please enable R2 through the Cloudflare
Dashboard"). Until it is, only the curated-series audio should be committed;
the `bible-365` bulk (365 files, ~1.4 GB) must wait.

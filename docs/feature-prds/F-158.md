## Problem

Founder:

> "I need to be able to preview both the next days Daily Bread, as well as
> Next weeks devotional as browser drafts, meaning in the 'finished state' on
> the browser so I can see exactly what it will look like — but with approve
> and reject still around each piece needing approval. I want a link in my
> settings to all the admin backend stuff. Go ahead and give me a backend so
> I can easily make edits myself."

Plus two constraints: "only I should be able to see drafts", and the go-live
rule — "the new daily bread goes live at 7 everyday. the weekly devotional
goes live 7 am monday." Silence publishes; rejection is the veto.

Before this feature: drafts were JSON blobs in a queue, the paper could not be
seen before it printed, `/admin` was a mockup with fabricated numbers, and
nothing enforced a go-live boundary at all — the paper flipped at midnight UTC
(8pm ET), which is not when a morning paper arrives.

## Solution

**One component renders the paper twice.** The whole edition was extracted
into `src/components/edition/EditionPage.tsx`; `/daily-bread` renders it live
(published-only reads) and `/admin/preview/daily-bread` renders it with
`preview` — same component, so the preview can never drift from what readers
see. Preview wraps reviewed items (lead, strip, practice) in approve/reject
chrome posting to the existing admin verdict API.

**The 7am flip** (`src/lib/edition/deadline.ts`): `effectiveEditionDate()`
computes the current edition in America/New_York — before 7am ET the site
still serves yesterday's paper; at 7am the new edition prints, and unrejected
drafts print with it (`draftIsLive`, `getLiveEdition`). Enforced at read time,
DST-safe, no cron.

**Monday 7am series release** (`.github/workflows/monday-release.yml`): dual
UTC crons + an ET-hour guard so exactly one fires at 7am ET Monday; merges the
open `reading gate` PR on `series/auto-*` (founder's veto = closing the PR)
and deploys, gated loudly on `CLOUDFLARE_API_TOKEN`.

**A real backend**: `/admin` is an honest hub (live draft counts, visible
failure states, mockups labeled NOT YET WIRED); `/api/admin/edition` gains
PATCH for in-place edits; the queue gets an Edit button (prose fields for
authored leads, JSON for the rest); Settings shows an ADMIN card only when the
admin probe returns 200. Drafts remain double-gated behind
ADMIN_EMAIL_ALLOWLIST — anonymous and non-admin users get 404.

**Redletter override**: a DB `redletter` row (once the blocked SQL lands)
overrides the page-side generator's pick, so an audited correction can replace
the computed saying without a deploy.

**Weekly series browser preview**: the Wednesday build uploads a preview
version of the Worker and comments the URL on the reading-gate PR, so next
week's devotional is readable in a real browser before Monday.

## Contracts

### Desktop

- `/admin/preview/daily-bread?date=YYYY-MM-DD` renders tomorrow's paper by
  default in finished state, with a datebar (prev/next) and per-item
  approve/reject chrome on reviewed kinds; deterministic modules render
  exactly as they will print.
- `/admin` shows the edition queue count from the live store, links to
  preview, queue, next-series override, and the GitHub reading-gate PR list.
- `/admin/edition` cards carry Edit: authored leads as prose fields
  (title/standfirst/body/pull-quotes), all other kinds as validated JSON;
  Save PATCHes and re-renders in place; server errors render verbatim.
- Settings surfaces an ADMIN card linking `/admin` only for the admin.

### Mobile

- The preview page is the same responsive EditionPage the paper uses; chrome
  bars stack above/below items and stay within the container at 375px.
- Approve/reject buttons are ≥44px touch targets.
- The admin hub and queue editor remain usable at 375px (single column).
- The crossword prints its clues beside the grid on desktop (the blank-half
  fix); mobile collapses them behind a class-driven toggle, never a
  `<details>` that leaves half the compartment empty.
- The preview page carries a fixed command bar: edition date, prev/next
  day, a live count of pieces awaiting a verdict, and REVIEW NEXT jumping
  between them; reviewable pieces are framed NEEDS YOUR EYE in plain
  English. The funnies placeholder fills its compartment (no dead zone).
- The NEXT SERIES steer box renders on /admin/edition (id `next-series`, the
  hub's anchor target) in both queue and empty states, wired to
  `/api/admin/edition/thematic` (GET current, POST set, DELETE clear) — and is
  test-pinned after a parallel rewrite erased the uncommitted original.

## Go-live rules (the founder's words)

- "the new daily bread goes live at 7 everyday" — `effectiveEditionDate()`.
- "the weekly devotional goes live 7 am monday" — monday-release.yml.
- "drafts go live if I dont directly approve" — rejection is the veto;
  approve is optional confidence.
- "only I should be able to see drafts" — preview route re-asserts the
  allowlist and 404s for everyone else; live route reads published-only plus
  drafts only once their edition date is live.
- Layout gates are NOT trusted alone: React renders layout and page
  concurrently, so `/admin` page markup could stream before the layout's
  `notFound()` aborted (measured in the Workers runtime). Every admin page
  now calls `assertAdminOr404()` itself (`src/lib/admin/assert-admin.ts`).
  Residual, accepted: Next resolves page `metadata` separately, so an
  anonymous request still sees the surface's title (e.g. "Edition Queue") on
  a 404-boundary body — surface names only, never content.

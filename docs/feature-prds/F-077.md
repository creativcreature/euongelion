## Problem

The brief makes security a Phase 1 deliverable, not a hardening pass:
webhook-driven entitlements need a drift-correcting reconciliation job
(§12.1); model spend needs a hard monthly cap with 50/80/100% alerting
(§12.6); CI needs a client-bundle secret audit and dependency scanning
(§12.5/§12.6). Separately (§9), the founder must be able to re-test
onboarding repeatedly via an admin-only "reset my account to first-run"
control with real gating (DB role + env flag, never obscurity). The
existing account-deletion cascade also missed `push_subscriptions` and
the active/scheduled/archived series tables.

## User Expectation

- Founder: one call resets my own account to a genuine first-run (data
  gone, account/subscription/role intact); nobody else can invoke it or
  target anyone else.
- Users: paid state never silently drifts from Stripe; runaway model
  spend is structurally impossible.

## 10/10 Definition

- Nightly `/api/admin/billing-reconcile` (internal-secret gated, GH
  Action scheduled): corrections only on positive Stripe evidence,
  ambiguous premium rows alert, errors touch nothing.
- Monthly spend wall inside `checkDailyBudget` (env
  `SOUL_AUDIT_MONTHLY_COST_BUDGET`, default $100) + one-per-month
  50/80/100% threshold alerts; honest monthly pause copy (not "come
  back tomorrow").
- CI: `verify:bundle-secrets` scans `.next/static` for secret names +
  value patterns post-build; `npm audit --audit-level=critical` fails
  the build.
- `/api/admin/reset-my-account`: env flag → auth → DB `users.role`
  check (manual grant only) → typed confirmation; caller-only; cascade
  preserves auth user + users row (subscription/role untouched), resets
  onboarding + free grant.

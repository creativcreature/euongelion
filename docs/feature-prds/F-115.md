# F-115: The Feature and Rack artwork was collapsed to zero height

## Metadata

- Feature ID: F-115
- Category: Reading surfaces
- Owner: founder
- Status: shipped (2026-08-16)
- Decision: SA-071
- Surfaces: `/series`

## Problem

> "There are missing images in Rack and Feature toggles."
> "Rack images still not showing" · "same with Feature on series"

The images were **never missing**. Every file was on disk, every `<img>` was in
the DOM, every one of them loaded, and nothing 404'd. They were rendering at
**zero height**.

Measured on the live site:

| Class                 | Rendered     |
| --------------------- | ------------ |
| `.fp-story-plate`     | 619 × **0**  |
| `.fp-desk-lede-plate` | 529 × **0**  |
| `.fp-desk-item-plate` | — × **0**    |
| `.rack-plate`         | 363 × **10** |

31 collapsed images in Feature, 37 in Rack.

## Cause

`Plate` renders `<Image fill>`, which is **absolutely positioned**. An
absolutely-positioned child contributes nothing to its parent's height, so a
plate container with no `aspect-ratio` and no explicit height has no height at
all — the artwork is clipped to a sliver by `overflow: hidden`.

Four of the seven plate containers were written without one:

| Class                 | Before                 | After     |
| --------------------- | ---------------------- | --------- |
| `.cover-plate`        | `aspect-ratio: 3 / 4`  | unchanged |
| `.issue-plate`        | `aspect-ratio: 4 / 3`  | unchanged |
| `.fp-lead-plate`      | `aspect-ratio: 21 / 9` | unchanged |
| `.fp-brief-plate`     | `aspect-ratio: 1 / 1`  | unchanged |
| `.fp-story-plate`     | **none**               | `3 / 2`   |
| `.fp-desk-lede-plate` | **none**               | `3 / 2`   |
| `.fp-desk-item-plate` | **none**               | `3 / 2`   |
| `.rack-plate`         | **none**               | `3 / 2`   |

`3 / 2` is the series artwork's own shape, so nothing is cropped to achieve it.

This is **not a regression** — the rules never carried a height. Checked at
`HEAD~1`, `HEAD~5` and `HEAD~15`: zero `aspect-ratio` lines in `.fp-story-plate`
at every one.

## Why the first fix missed it

The earlier pass (F-114) counted **elements**, not pixels: 37 links against 37
`<img>` tags read as healthy. An image can be present, loaded and decoded and
still be invisible. **Measure rendered height, not element count** — a plate
under 40px tall is a bug regardless of what the DOM says.

## Contracts

### Desktop

- Every plate container that holds a `fill` image declares a height.
- Feature's story, desk-lede and desk-item plates render at 3:2.
- Rack's plates render at 3:2, so each folded paper shows its artwork.

### Mobile

- The ratios are intrinsic, so the plates scale with their column and hold at
  390px with no overflow.

## Acceptance criteria

- [x] Zero images wider than 60px rendering under 40px tall in any `/series` view
- [x] Feature: 37 images, median rendered height 152px
- [x] Rack: 37 images, median rendered height 251px
- [x] All 37 painted (`complete && naturalWidth > 0`) in both
- [x] No horizontal overflow at 390px

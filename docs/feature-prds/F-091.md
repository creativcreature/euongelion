# F-091: One Daily Bread in the nav; Daily Bread leads with artwork

## Metadata

- Feature ID: F-091
- Category: Navigation / Reading experience
- Owner: founder
- Status: in progress (2026-08-15)
- Decision: SA-045
- Surfaces: global nav, mobile tab bar, `/daily-bread`

## Problem 1 — two nav items, one destination

Founder: _"Daily Bread and Today are the same menu item. remove the
redundancy, instead of calling it today, call the item Daily Bread."_

`DESKTOP_NAV_ITEMS` carried both:

```ts
{ href: '/daily-bread', label: 'TODAY' }
{ href: '/daily-bread', label: 'DAILY BREAD' }
```

Same `href`. Because the active-state check matches on path, **both lit as
active simultaneously**, so the nav showed two underlined items pointing at one
page — it read as a rendering fault rather than a menu.

`MobileTabBar` had the same destination under the label `TODAY`.

### Fix

The `TODAY` entry is removed from the desktop nav and the mobile tab is
relabelled `DAILY BREAD`. One name, one destination, one active state.

SA-033's ruling is unchanged and still correct: "today" means *your* devotional
resolved through Daily Bread, not the `/today` editorial rotation. That
rotation stays reachable as "Today's Edition" in the footer, and the `/today`
route is untouched so existing links keep working.

## Problem 2 — Daily Bread opened on a wall of text

Founder: _"the layout on daily bread/today is incorrect"_, and separately, of
the reading surfaces: _"It was leading with an image."_ The reference given for
a correct layout was `/devotional/community-day-1`.

Every devotional opens with `DevotionalHeadline` — artwork left, title,
standfirst and scripture right. `/daily-bread`'s empty state (the view a reader
without an active series gets) hand-rolled its own markup with **no image at
all**: a kicker, a scripture line, an `h1` and two paragraphs. The two surfaces
did not read as the same product.

### Fix

The empty state now renders the same `DevotionalHeadline` the reader uses, fed
by `getSeriesHero()`. Same component, same proportions, same order — title,
standfirst, scripture — so Daily Bread and a devotional page are recognisably
one design.

## Platform contracts

### Desktop

Nav renders a single `DAILY BREAD` item, active only when on `/daily-bread`.
The Daily Bread empty state leads with the series plate in the 2fr column and
the title block in the 1fr column, matching `/devotional/[slug]`.

### Mobile

The reading tab is labelled `DAILY BREAD`. The headline collapses to one column
at ≤900px with the art ordered after the title, per SA-037 — nothing precedes
the title on a phone.

## Known gaps

**31 of 37 series hero images are the wrong aspect for the headline slot.**
The slot is `aspect-ratio: 1408/768` with `object-fit: cover`. 28 heroes are
square `1024×1024` and 3 are portrait (`768×1408`, `928×1152`), so they are
hard-cropped — roughly 45% of a square plate's height is discarded, which is
why some devotionals read as badly framed while `community-day-1`
(`1408×768`, native) looks right. Only ~6 series are correctly landscape.

This is an asset problem, not a layout one, and the fix is a founder call:
regenerate landscape heroes (~31 plates via the devo-go riso pipeline), derive
16:9 crops from the square masters, or accept the crop. Not actioned here.

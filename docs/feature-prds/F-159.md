## Problem

The top-of-page banner has been the static empty-tomb riso since R38. The
founder's direction (2026-08-19): _"I want the main header image, to be a
differnt image evrytime the page loads. It should rotate between headers. The
headers need to be various biblical representations of The Gospel."_ Same
style, same density, same exact colors as the tomb — different compositions
and subjects, no modern people, compositions derived from cinema stills.

## Solution

**Seven plates, one press run.** The tomb stays as the anchor; six new plates
join it, chosen by the founder from a 26-candidate illustrated proposal (each
candidate carried a composition sketch at the banner's true ratio, scripture,
gospel logic, and a verified FILMGRAB reference still). The chosen six:
Passover doorframe, the fourth man in the furnace, the Jordan baptism under a
torn sky (a literal restage of the O Brother river-baptism frame), Moses
parting the sea (swapped in for the finished cross by founder direction,
2026-08-20 — the crucifixion master stays archived), the true vine, and
Christ carrying his cross staged in the Seventh Seal's ridge-procession
frame.

**Constants held across the set:** subject dead center (founder ruling),
cobalt/cream duotone with crimson misregistration, the tomb's ~75%+ ink
register, one light source with a story, ancient-Levant figures only, all
devo-go prompt blocks. Generated through the imagen skill (Codex built-in
image_gen at a forced 3:1, zero credits), center-cropped and
Photoshop-upscaled 1.105× to exactly 2400×658.

**The draw is a parse-time inline script.** The server-rendered banner div
carries a script that injects the `<img>` synchronously with a random pick
from `HERO_ROTATION` — the page stays statically renderable and cacheable,
every load draws fresh, there is one image fetch, no flash, and no hydration
surface. `fetchpriority="high"` preserves the LCP contract;
`<noscript>` serves the tomb.

**The pool is pinned.** The 20 unchosen candidates live in
`docs/HERO-ROTATION-CANDIDATE-POOL.md` with their reference stills in
`content/reference/hero-rotation-stills/` — founder: a large pool to pull
from later. Masters archived in `content/reference/hero-rotation-finals/`.

## Platform Contracts

### Desktop

- The banner keeps its `3358/920` aspect box (`.homepage-hero-banner-art`);
  the injected image fills it under the existing `object-fit: cover` rules.
- Every reload may draw a different plate; all seven resolve and render at
  the banner's native ratio with no letterboxing and no layout shift.

### Mobile

- Same aspect box (~103px tall at 375px width); the dead-center subject rule
  keeps every plate's subject legible under the narrow crop.
- No additional network cost versus the static hero: exactly one plate is
  fetched per load.

## Responsive plate derivatives (reconciled to git 2026-08-26)

The banner paints via CSS `background-image`, which gets none of the
negotiation an `<img srcset>` would, so a phone was pulling the full 2400px
plate — 381-618 KB for a decorative band ~103px tall, and it is the LCP
element. Each of the seven plates now ships `-960` and `-1600` derivatives
beside the 2400px base; the draw script publishes all three as
`--hero-rot-sm` / `--hero-rot-md` / `--hero-rot` and preloads only the width
the matching media query will actually paint (a preload that disagrees with
the query spends the LCP budget twice). The 960 derivative is ~70-128 KB,
about 81% smaller, and is still 2x the widest phone the banner renders on.

**Reconciliation note.** The CSS half of this (the three-property fallback
chain in `globals.css`) was committed earlier; the JS half
(`src/lib/home/hero-rotation.ts`) and all 14 derivative files were live in
production but had never been committed — production had been deployed from
the shared working tree. Verified 2026-08-26: `header-v2-960.webp` (71,724 B),
`header-v2-1600.webp` (222,294 B), `hero-vines-960.webp` (131,248 B) and
`hero-red-sea-1600.webp` (303,672 B) all served 200 from euangelion.app while
absent from `git ls-files`. A clean-checkout deploy would have 404'd every
hero background below 1100px. Now committed so git and production agree.

All 7 plates x 2 widths = 14 files, verified present and matching the
`HERO_ROTATION` list exactly.

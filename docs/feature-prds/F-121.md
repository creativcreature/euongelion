# F-121: The blue italic line under the lead scripture is gone

## Metadata

- Feature ID: F-121
- Category: Reading surfaces
- Owner: founder
- Status: shipped (2026-08-17)
- Decision: SA-077
- Surfaces: `/devotional/[slug]`, every reader rendering a `scripture` module

## Problem

> "devotionals have a wierd blue text below the lead scrioture. appears to be a
> mistake… unnecessary pull quotes in an italic small font. I need it removed on
> all devotionals relevant."

Then, on being told it was the transliteration line:

> "That isnt transliteration if the hebrew sentence doesnt appear."

Both correct.

## What it was

`ScriptureModule` rendered `module.transliteration` in two places — once paired
with `greekOriginal`, once with `hebrewOriginal`:

```jsx
<p
  className="mt-2 vw-small italic"
  style={{ color: 'var(--color-gold)', opacity: 0.85 }}
>
  {module.transliteration}
</p>
```

It read as a mistake because of how it was styled, not what it said. `vw-small`

- `italic` + `--color-gold` — and **`--color-gold` resolves to cobalt in light
  mode** — put a small blue italic line immediately under the passage, visually
  indistinguishable from a stray pull quote:

> _vedarkekha — "in your way"_

## The founder's second point is the substantive one

A transliteration is only a transliteration of what is actually shown. Measured
across all 26 occurrences:

| Shape                                                  | Count  | Example                                                  |
| ------------------------------------------------------ | ------ | -------------------------------------------------------- |
| Original is a **single word or short phrase** + gloss  | **25** | `בְדַרְכְּךָ` → _vedarkekha — "in your way"_             |
| Original is a **full verse**, genuinely transliterated | **1**  | 11 Greek words → 11 matching words (`bible-365-day-286`) |

So in 25 of 26 cases this was never a transliteration of the passage. It was a
**word study** — a lemma plus its meaning — which is exactly what the WordNote /
vocab modules already do properly, in the right place, with lexicon grounding.
It was duplicated content wearing pull-quote styling.

Zero of the 26 lacked an original-language line, so nothing was orphaned text;
the mismatch was one of _scope_, not of presence.

## What changed

Both render blocks are removed from `ScriptureModule.tsx`. Nothing else.

- **The `transliteration` field stays in the JSON.** Restoring the block alone
  brings it back; no content was destroyed. This also keeps the change off the
  content files, which another session is actively editing.
- **Vocab / WordNote transliterations are untouched.** The field name appears in
  532 devotionals, but only 26 instances sit on a `scripture` module. The other
  ~506 belong to word-study features and are unaffected.
- **The original-language lines still render** — Greek and Hebrew both keep
  their existing muted styling.

## A rule this retires

The comment above the block asserted a project rule:

> "Hebrew/Greek must never appear without transliteration alongside it."

That rule no longer holds, and the code says so now rather than claiming a
constraint it does not follow. The original language stands alone. If the intent
was pronunciation support, the correct home is the WordNote module, which
already provides it with a transliteration _and_ a lexicon entry.

**One case worth a second look:** `bible-365-day-286` was the single genuine
full-verse transliteration. It is removed along with the rest per "all
devotionals relevant" — restoring just that one is a data-level change if
wanted.

## The larger half: the emphasis-tag row

The transliteration line was only 25 devotionals. The founder's screenshot
pointed at a second, much bigger offender directly beneath the reference:

`module.emphasis` rendered **twice** — once as the highlighted words inside the
passage (`gold-shimmer`, which stays), and again as a wrap-row of those same
phrases below the reference:

```jsx
<div className="mt-6 flex flex-wrap gap-3">
  {module.emphasis.map((word, i) => (
    <span className="vw-small italic"
          style={{ color: 'var(--color-gold)', opacity: 0.7 }}>
```

Same token trap — `--color-gold` is cobalt in light — so every emphasised phrase
appeared a second time in small blue italic, reading exactly like a pull quote
nobody wrote. _Peace and security._ _break up your unplowed ground._

**Scope: 529 of 575 devotionals, 1,785 chips.** That is the "all devotionals
relevant" the founder meant.

Both render sites removed (the two variants differ in formatting, so they had to
be matched separately). `module.emphasis` still drives the in-passage
highlighting through `renderPassage()`, and the field is untouched in the JSON —
verified after removal: **0 chip rows, 0 transliteration lines, 5 in-passage
highlights intact.**

### A verification note worth keeping

The first check after the rebuild still showed 2 chip rows, and I nearly went
hunting for a second component. The served HTML had **zero** — the browser was
holding a **service-worker cached page**. `curl` the origin before believing the
DOM.

## Contracts

### Desktop

- No transliteration line renders beneath a scripture passage.
- Greek and Hebrew original lines render unchanged.

### Mobile

- Same; the removed line took vertical space on the smallest screens, so the
  passage now sits closer to the artwork below it.

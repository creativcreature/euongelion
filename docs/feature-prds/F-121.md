# F-121: Touch hit pads painted blue slabs over the /series switcher

## Metadata

- Feature ID: F-121
- Category: Platform
- Owner: founder
- Status: shipped (2026-08-17)
- Decision: SA-077
- Surfaces: `/series` (the reading room switcher and sort row)

## Problem

Founder, with a screenshot of `/series` on iPhone: **"I need this fixed."**

The view/sort switcher was covered in translucent cobalt rectangles. They were
larger than the controls they sat on, staggered, and overlapped the row
beneath — the SORT row and the wrapped LONGEST button were both buried under
slabs. The art-directed "plates in a type case" toolbar was unreadable.

This is **not** a recurrence of F-120. That was the browser's tap highlight plus
a sticky `:hover`; both were fixed and both remained fixed. This is a third,
independent cause with the same symptom colour, which is why it survived F-120.

## Root cause: two systems fighting over one `::after`

Three facts had to line up.

**1. `EditorialMotionSystem` claims `::after` on every paper button at runtime.**

```ts
// src/components/EditorialMotionSystem.tsx
const INTERACTIVE_SELECTOR = ['.mock-paper button' /* … */].join(', ')

const prepareInteractive = (node: HTMLElement) => {
  node.classList.add('ink-line-interactive')
  node.classList.add(node.tagName === 'A' ? 'ink-link' : 'ink-button')
}
```

The `/series` toggles are `.mock-paper button`, so every one of them is
decorated after hydration. Nothing in `SeriesBrowser.tsx` shows these classes —
they only exist at runtime, which is why the bug is invisible in the source.

**2. That class's `::after` is a gold hover underline, held invisible by a
collapsed transform.**

```css
.ink-line-interactive::after {
  height: 1px; /* a hairline */
  background: color-mix(in srgb, var(--color-gold) 68%, currentColor);
  transform: scaleX(0); /* collapsed to nothing at rest */
}
```

**3. The 2026-08-16 touch-target sweep minted a 44px hit pad on the _same_
`::after`.**

```css
@media (pointer: coarse) {
  .rr-view::after,
  .rr-sort::after {
    top: 50%;
    left: 50%;
    width: max(100%, 44px);
    height: max(100%, 44px); /* overrode height: 1px  */
    transform: translate(-50%, -50%); /* overrode scaleX(0)    */
  }
}
```

Both overrides are fatal, and they compound:

- `height: 1px` became `44px` — the hairline became a slab.
- `transform: scaleX(0)` became `translate(-50%, -50%)` — the thing that kept it
  invisible was replaced by the thing that centred it, so the slab **un-collapsed
  and painted**.
- The `background` survived untouched. `currentColor` on these controls is the
  cobalt ink, so the slab was blue.

Because the pad is 44px tall on controls that render 35px (views) and 25px
(sorts), each slab overhung its control by **4.4px** and **9.6px** on every
side. The sort row's overhang (9.6px) exceeds the row gap (`0.55rem` = 8.8px),
so the slabs reached into the row above and below. That is exactly the founder's
screenshot.

The measured background confirmed the mechanism before any code changed:
`color(srgb 0.106 0.145 0.445 / 0.942)` — the `color(srgb …)` form is what
WebKit computes a `color-mix()` down to, which no other rule in the block could
have produced.

## The fix

Move the hit pad to `::before`, which no rule claims on any of these three
selectors, and let `::after` go back to being the ink underline. One
pseudo-element per owner.

Deliberately **not** done:

- **Neutralising the paint** (`background: none` on the pad) would have hidden
  the slab while leaving two systems writing to one box — the same landmine, now
  disguised, for whoever next adds an `::after` rule here.
- **Opting the controls out of the ink layer** (`data-no-ink-line="true"`) would
  have fixed touch by deleting the gold hover underline on desktop, which the
  founder never asked to change.

`.mock-icon-control` is included in the move even though it is currently safe —
it escapes decoration only because `shouldSkipInteractive` excludes
`.mock-topbar`. Putting its pad on `::before` too means that exclusion is no
longer load-bearing.

## Verification

Reproduced and verified in **WebKit + iPhone 14 emulation**, against production
first (to confirm the live cause) and then against the local build (to confirm
the fix). Chromium was used for the local pass because the app sends
`Strict-Transport-Security` on localhost as well, and WebKit honours HSTS for
localhost — it upgrades every `http://localhost` subresource to `https`, which
fails TLS and leaves the page unstyled and unhydrated.

| Check                                         | Before                            | After                    |
| --------------------------------------------- | --------------------------------- | ------------------------ |
| `.rr-view::after` height                      | `44px` (slab)                     | `1px` (hairline)         |
| `.rr-sort::after` height                      | `44px` (slab)                     | `1px` (hairline)         |
| `::after` background                          | `color(srgb 0.106 0.145 0.445 …)` | unchanged, but collapsed |
| `::after` transform                           | `translate(-50%, -50%)`           | `scaleX(0)`              |
| `::before` hit pad                            | absent                            | ≥ 44×44, transparent     |
| Vertical overhang, views                      | 4.4px each side                   | none painted             |
| Vertical overhang, sorts                      | 9.6px each side                   | none painted             |
| All 7 view taps activate the right view       | yes                               | yes                      |
| All 5 sort taps activate the right sort       | yes                               | yes                      |
| Tap 3px **above** a 35px icon still activates | —                                 | yes (pad is real)        |

A site-wide sweep of eight routes for the same collision — any
`ink-line-interactive` element whose pseudo-element paints taller than a
hairline — found no other instance. `.link-highlight::before` registers on the
detector but is a designed highlighter swash, collapsed by `scaleX(0)` at rest
and proportional to its text.

## Contracts

### Desktop

- Untouched. The hit-pad block is `pointer: coarse` only, so no rule in this
  change is ever evaluated on a mouse pointer.
- The gold hover underline still animates on `::after`, at 1px, as designed.

### Mobile

- No painted slab on any `/series` control at any width.
- The 44px minimum touch target on `.rr-view`, `.rr-sort` and
  `.mock-icon-control` is preserved, and remains genuinely hittable outside the
  visual box — not merely declared.
- No visual pixel of the switcher moves. The pad is transparent.
- The active view/sort toggle keeps its `.is-active` fill.

### Both

- The hit pad may never again be minted on `::after` for a control that
  `EditorialMotionSystem` decorates.

## Acceptance criteria

- [x] No painted slab on any `/series` control at 390px

- [x] `::before` resolves to ≥ 44×44 and transparent
- [x] Every view and sort toggle still activates from a tap

- [x] Regression test locks the pseudo-element split
- [x] Type-check, lint, contract and tracking gates clean

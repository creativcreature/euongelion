# F-155: Audio gets its own area, and gets out of the way

## Metadata

- Feature ID: F-155
- Category: Reading surfaces
- Owner: founder
- Status: wip
- Decision: SA-109
- Surfaces: `/series`, `/series/[slug]`, `/` (homepage), `src/components/audio/AudioDrawer.tsx`, `src/components/audio/OccasionPicker.tsx`

## Problem

Founder, 2026-08-19, on the previous pass:

> "the listen and what are you doing on the Series page should not be ther.
> Audio should be a seperate area (sidebar) non intrusive. This placement is
> extremely intrusive."

He was right, and the error is worth naming precisely. The earlier work put a
bordered **Listen** call-to-action in the series meta-action row and a full
**"How long have you got? / What are you doing?"** picker above the series
shelves. Both were reasoned from real research — every studied audio product
puts play beside read — but that research came from _audio-first_ products.
This is a reading site with audio in it. Copying the placement copied a posture
that does not belong here.

## Solution

**Both removed from the series pages.** The Listen CTA is gone from
`/series/[slug]`; the occasion picker is gone from `/series`. Nothing about
audio is injected into a browse surface any more.

**Audio has exactly one home: a sidebar.** On anything with room it is a
right-anchored panel, full height, sliding in from the edge. On a phone it stays
a bottom sheet, because a right-hand sidebar at 375px is a full-screen panel
anyway and a thumb is at the bottom.

**Discovery moved inside it.** The picker is now a compact section within the
sidebar rather than a surface of its own — it lost its rule, its display
heading and its vertical rhythm, because inside audio's own area it is a
section, not a headline.

**The sidebar opens with an empty queue.** This is the consequence that had to
be designed for: removing the picker from `/series` removed the only way in, so
the panel can no longer require something to be playing. The homepage callout's
button now opens it rather than navigating.

**What deliberately stayed.** The small `+` on a series day row — that is how a
reader adds while navigating, which the founder asked for explicitly, and one
icon in a card corner is not the intrusion he objected to. The tucked handle
also stays: it appears only when something is queued, and it is the thing that
makes audio "not invisible".

## The sidebar was invisible in a real browser — SA-112

Shipped, verified green in jsdom, and **did not open for anyone with an ad
blocker.**

The container class was `.ad-root`. Ad blockers ship cosmetic filters that match
that exact string and inject `display: none !important` from the **user**
origin, which beats author `!important`, beats an inline style, and never
appears in `document.styleSheets` — so nothing on the page can see it or
override it.

Measured in Chrome against production: a bare `<div>` appended to `body`
computes `display: block`; the identical div classed `ad-root` computes `none`;
`ad-drawer` and `ad-handle` are untouched. It is that one string on a filter
list.

The unit tests could never have caught it — jsdom has no ad blocker. What caught
it was opening the deployed page in a browser and clicking the button, which is
the only check that was ever going to.

**Every class in the component is now prefixed `lsn-`.** Never prefix a class
`ad-` here.

## Platform Contracts

### Desktop

- Right-anchored sidebar, `min(26rem, 92vw)`, full height, slides from the edge.
- Escape closes it. The grip is hidden — it is not a sheet here.

### Mobile

- Bottom sheet, unchanged, capped at 78vh.
- Every control keeps its 44px target.

## Acceptance

- [x] No Listen CTA on `/series/[slug]`.
- [x] No occasion picker on `/series`.
- [x] Sidebar on desktop; bottom sheet on mobile.
- [x] Picker is a compact section inside the sidebar.
- [x] Sidebar opens with an empty queue; transport and queue controls hidden
      when there is nothing to control.
- [x] Homepage callout opens the sidebar instead of navigating.
- [x] Class prefix is `lsn-`, not `ad-` — see above.
- [x] `panelOpen` is not persisted — a sidebar that reopens itself on load is
      the same intrusion in a different form.

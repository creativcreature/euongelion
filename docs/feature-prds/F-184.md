## Problem

The founder asked for the Daily Bread to become a real daily publication and for the
comic, which "doesn't load", to be fixed. The SA-090 paper re-computes itself on every
request, derives "Vol. · No." from the calendar (No. resets every 1 January), keeps no
frozen archive (an archived date re-renders with today's code and data), and depends on
a strip pipeline that has produced no rows for weeks. There was no record of how any
day's paper was made and no way to tell a degraded day from a normal one.

## Solution

- **Serialized editions.** One row per editorial date in `daily_bread_editions`.
  Native V2 issues start at Vol. 1 · No. 001; the number is allocated inside the
  publication transaction under an advisory lock and never reused. Backfilled
  editions are archive entries and never take a number.
- **Frozen snapshots.** A published edition renders from its stored document.
  Corrections write immutable revisions (trigger-enforced); withdrawal keeps the
  number retired and shows the reason.
- **Lifecycle ⟂ quality.** draft → assembling → ready → published → superseded,
  independent of normal / fallback / minimum. A fallback edition says so in its
  colophon.
- **Pipeline.** A 7am America/New_York editorial clock; a scheduler step that builds
  tomorrow in the 14 hours before rollover and publishes after it; an assembly lease;
  a PublicationAttempt row for every attempt (providers, fallbacks, stage timings,
  module failures, cost).
- **Generator chain.** Claude API → Claude Code CLI → OpenAI `gpt-5-mini` → Gemini →
  a deterministic floor, behind `EditorialGenerator`. Timeouts, one retry, output
  validation. The model writes only the editorial frame (deck, rabbit-hole reasons,
  scene choice), the Sunday lead and the guides. Scripture text is always looked up in
  the BSB, never generated. An edition whose frame Claude did not write is `fallback`.
- **The comic is Echo & Dust, weekly.** One founder-approved strip, dated a Monday,
  prints every day of that week. A week without one reprints a single approved strip
  all week, credited, avoiding the three weeks before. Otherwise the section is
  omitted. Strips are approved in batches at `/admin/comics`. The first build replaced
  Echo & Dust with wordless SVG parable templates; those are removed. Frozen editions
  that stored an SVG strip still render it. The art style (code-drawn or Codex) waits
  for the founder's verdict.
- **Composition.** Eight structurally distinct archetypes (Broadsheet, Illuminated,
  Quiet, Field Notes, Red Letter, Study Table, Joy, Prayer Book), seeded choice with
  anti-repeat scoring, module tiers and band rhythm.
- **Procedural visual engine.** First-party WebGL scenes (Living Water, Grain,
  Wilderness Stars) with riso, halftone and ASCII renderers; a static SVG poster is
  always painted first; reduced motion, off-screen pause, 30 fps cap, DPR cap, context
  loss handled. No image model at request time.
- **Security.** Service-role writes only; RLS public read of published rows only;
  pipeline functions revoked from client roles; internal-secret publish endpoint with
  date-window validation and rate limit; safe links and assets; redacted logs;
  document validation rejects credential-shaped strings and script content.

## Platform Contracts

### Desktop

- Six-column band grid; each archetype sets its own measure, band order and
  hierarchy. Previous/next edition navigation and the archive under every paper.
- The procedural scene animates only when visible, motion is allowed and WebGL comes
  up; otherwise the poster stays.

### Mobile

- Every band collapses to one column at 900px; a stored SVG strip swaps to stacked
  panels below 700px; the archive list stacks serial, date, title, archetype. No
  horizontal overflow at 320px, measured on three emulated phones
  (`docs/daily-bread/QA-2026-09-14-MOBILE-ACCESSIBILITY.md`). Touch targets on edition
  navigation and the contents line are at least 44px. LCP on plate-led editions is
  about 7.4 s on Slow 4G (target 2.5 s), waiting on a founder decision.

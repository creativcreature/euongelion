## Problem

SA-059 swapped the two routes at the founder's direction: `/today` became YOUR
reading and `/daily-bread` became the shared edition. **The component folders did
not move.** So:

| Route                      | Rendered from                 |
| -------------------------- | ----------------------------- |
| `/today` (your plan)       | `src/components/daily-bread/` |
| `/daily-bread` (the paper) | `src/components/edition/`     |

The folder named `daily-bread` served `/today`, and the folder serving
`/daily-bread` was called `edition`. Reading the tree gave you the information
architecture backwards.

This is not hypothetical. On 2026-08-19 it misled **this** session, with the code
open: a progression bug was diagnosed against the wrong page and reported to the
founder that way, who corrected it. Anything reading the tree — a new session, a
new agent, a person — inherits the same wrong model.

## Fix

`git mv src/components/daily-bread src/components/today`, and the seven importers
rewritten. `edition/` already named its route correctly and is untouched.

Chosen now because the blast radius was checkable and small: seven files, **none**
of them held by another session at the time. A rename is cheap when nothing else
is in flight and expensive when something is.

## Known residue

`DailyBreadView.tsx` keeps its name inside `components/today/`. It renders the
Soul Audit plan path of `/today`, so the name is now wrong at the file level too
— but the folder was the load-bearing confusion, and renaming the component as
well would have widened the diff for less benefit. Worth doing in the same quiet
window as any future work on that component.

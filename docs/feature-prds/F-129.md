### 45 · Recent searches, and 47 · suggested queries

The overlay opened onto a single hint line. Every search in the Mobbin scan —
[Best Buy](https://mobbin.com/screens/9c740f17-1c66-4e84-86f7-f97cd825986e),
[IKEA](https://mobbin.com/screens/fc1d9403-042c-4a2f-bacd-1b455c19ec4a),
[Matter](https://mobbin.com/screens/1f3f1157-0870-45e7-afff-0c1fc6633bae) —
gives the empty state something to act on, because the second search for a
thing is more common than the first and retyping is the entire cost.

- **Recents** are recorded when the reader _opens a result_, not on every
  keystroke — that is the signal the query was worth keeping. Six maximum, most
  recent first, with a CLEAR control.
- **Stored in this browser only.** The search box is the one place a reader may
  type something they would not want on a server, and after this week's privacy
  work the site's copy has to stay true.
- **Suggestions are real series names**, read from `SERIES_ORDER`. The empty
  state teaches the actual corpus rather than inventing example prose — which
  also keeps this inside the founder's "don't change the content" rule.

### 53 · Uppercase label tracking had two sources of truth

`.text-label` declared `letter-spacing: 0.12em`; `.mock-home .text-label`
overrode it to `0.04em`. The newspaper shell wraps **25 of the ~32 surfaces**
that use the class, so the same label rendered two different ways depending on
which shell it happened to sit in, and the base value was effectively dead
outside admin and onboarding.

Now one `--track-label` token at the shell's value — the design as it actually
reads. Onboarding and the admin pages tighten to match everything else.

### 55 · The drop cap had only half its optical alignment

`transform: translateY(0.08em)` was already lifting cap-bottom to body
x-height. The horizontal half was missing: a serif cap carries a left side
bearing, so the glyph sat a couple of pixels inside the text column it is meant
to align with and the paragraph edge read as ragged. `margin-left: -0.05em`
pulls the ink flush with the measure rather than the glyph box.

### 56 · Hanging punctuation reaches the reader's pull quotes

`.type-prose` already declared `hanging-punctuation: first last`, but the
reader's blockquotes are `.font-reading` and never inherited it. The oversized
decorative quote mark `PullQuote` renders is a separate thing and already hangs
correctly; this is about the quote character in the text itself.

Support is still WebKit-only, which is why the existing `text-indent` fallback
carries the same intent elsewhere. Both are harmless where unsupported.

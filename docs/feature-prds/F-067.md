## Problem

Reader SSR is deliberately disabled over a serialization bug on one devotional (`too-busy-for-god-day-6`) so every reader page flashes a client loader (LCP + polish hit). All type/theme controls live in global Settings; there is no in-reader adjustment.

## User Expectation

- The page opens with the words already there (no loader flash).
- An "Aa" control inside the reader offers a few curated, named reading themes (Apple Books model: named presets, not raw sliders).

## 10/10 Definition

- SSR on for all devotionals; root cause of the serialization bug fixed (no slug special-cases); corpus-wide serialization scan passes.
- "Aa" sheet with 3-4 named themes (e.g. Ink, Parchment, Vellum, Night), persisted, light/dark aware, reduced-motion safe.

## Methodology References

- M00 (canonical IA / navigation UX)
- Mobbin anchors: Apple Books named presets; Fable; The Athletic

## Device Contracts

### Desktop

- Aa control in the reader chrome; sheet as popover.

### Mobile

- Aa opens a bottom sheet; safe-area aware; ≥ 44px targets.

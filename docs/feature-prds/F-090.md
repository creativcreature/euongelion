# F-090: The library — active day, browsable series, phrase search, rotating feature

## Metadata

- Feature ID: F-090
- Category: Reading experience / Browse
- Owner: founder
- Status: in progress (2026-08-14)
- Decision: SA-044
- Surfaces: `/series`, `/` (featured rail), `/library` (ACTIVE card), every MARK READ

## Problem

Four founder asks in one night, all variations on _the app knows the right
answer and shows a different one_.

> The Active devotional should always show the active day as well. Not just
> default to day one. If I mark it done, the next day should show.

> The series page needs revamp as series are hiding. I want it to function like
> a library of magazines, be more interactive and better searchable… 2 views, 1
> is the full library alphabetical and sortable in various ways, and 2 is a
> list. actually add a feature style as well that shows it more bento box
> style… I also want the user to be able to search by phrasing etc so they can
> find the most relevant devotionals — this is NOT the soul audit.

> I need the homepage featured series to be dynamic. New series in the features
> each refresh, except the latest uploaded should always be the first shown on
> homepage.

## What was actually broken

| Symptom                                     | Cause                                                                                                                              |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| The active day never advances               | `PATCH /api/devotionals/active` accepts `currentDay` and has since 2026-05-14 — **no client ever called it**. Completion lived only in `localStorage`, which the server never sees. |
| "Day 3" links to day 1                      | The library ACTIVE card printed the day, then linked to a bare `/daily-bread`; a saved series resolved to `/series/<slug>`, the top of the arc. |
| Series hiding                               | The default rails view was a handful of curated sideways shelves over 37 series. Anything in no rail was unreachable without switching views and knowing to look. |
| Search finds nothing useful                 | `searchDevotionals` is AND-semantics: **"I feel anxious about money" returned zero results**, because no teaser contains the token `i`. |
| Homepage lead is stale                      | `HOMEPAGE_TODAY` was a literal in `src/app/page.tsx`; it still named `he-cannot-deny-himself` after a newer series shipped, and the rail never varied. |

## Scope

**In:**

- `src/lib/reading/active-day.ts` — locate / label / link a day, and advance the
  server day after completion. Wired at `markDevotionalComplete`, the one choke
  point every MARK READ path already goes through.
- `src/components/series/SeriesBrowser.tsx` — FEATURE (bento) / LIBRARY / LIST
  plus phrase search. `/series/page.tsx` becomes a shell.
- `searchLibraryByPhrase` in `src/lib/global-search.ts` — stopword-dropping,
  OR-scored with squared coverage, exact-phrase bonus, over series **and**
  devotionals.
- `src/lib/series/catalog.ts` — six sorts, recency, filing title, A–Z buckets.
- `src/lib/home/featured-rotation.ts` — client-side rotation, newest eligible
  series pinned first.
- 36 tests across three files; service worker v67.

**Out:** the Soul Audit (untouched); `src/data/series-rails.ts` (kept, no longer
the default way in); `HOMEPAGE_TODAY`'s main editorial block (still hand-written
copy — only the rail beneath it rotates).

## Design decisions worth keeping

- **Never fall back to day 1.** `activeDayHref` links to the SERIES page when a
  day cannot be resolved. Silently restarting a reader three days in is what
  made the original bug look like working software.
- **"Next day" is the first incomplete day**, not last-completed + 1, which
  skipped gaps when someone read out of order.
- **Rotation must be client-side.** The homepage is edge-cached for a year, so a
  render-time shuffle is frozen into the cache and identical for everyone; and
  `Math.random()` in render is a hydration mismatch.
- **Both search scorers stay.** The precise AND scorer is still right for
  known-title lookup; the loose one is for describing a need.
- **Filing drops leading articles for the sort AND the bucket.** When only the
  bucket stripped "The", the A–Z rail read `… R S N W T V`.
- **Tile type uses a fixed accent, not `--color-gold`** — that token is a legacy
  alias resolving to cobalt `#1f2a8d` in light mode, which rendered kickers
  near-invisible on the always-dark scrim.

## Risks

| Risk                                          | Mitigation                                                                                                                        |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Anonymous readers have no `active_series` row | The advance reports `not-applicable`, a real state, and local progress still stands. Not an error.                                 |
| Re-reading an earlier day drags the place back | The advance runs only when the finished day is at or past the server's current day.                                               |
| A rotating rail feels random rather than editorial | The lead is pinned and the tail is drawn from the whole catalog; the bento rhythm is a fixed pattern, not a shuffle.          |
| Phrase search mistaken for the Soul Audit     | Stated in the UI beneath the field, and it generates no plan.                                                                     |

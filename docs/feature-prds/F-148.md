# F-148: A build without its client config must fail, not ship

## Metadata

- Feature ID: F-148
- Category: Platform
- Owner: founder
- Status: shipped (2026-08-19)
- Decision: SA-102
- Surfaces: every build; auth pages most visibly

## Problem

Founder, 2026-08-19: Google sign-in was enabled, coded, flagged `true` — and
absent from production.

`NEXT_PUBLIC_*` is **inlined at build time**. `.env.local` holds these values and
is gitignored. A Cloudflare Worker secret does nothing for them. So a build from
a fresh clone, a CI runner, or a **clean git worktree** silently succeeds and
emits a bundle with:

- no Supabase client configuration
- no "Continue with Google"

Nothing fails. The deploy reports success. The only way to notice is to go
looking for a feature in production and find it gone.

That is what happened: the live `v127` build was made without `.env.local`. A
local build **with** it inlines "Continue with Google" into 2 chunks and the
Supabase host into 3 — proving the code and the flag were correct all along and
the artifact was not.

The irony is that a clean-checkout deploy — introduced deliberately so one
session could not ship another's uncommitted work — is exactly the path most
likely to omit a gitignored file.

## Fix

`scripts/check-public-config.mjs`, first in the `build` chain.

It reads the env files itself, in Next's precedence order, because Next loads
them internally and a pre-build script would otherwise see an empty
`process.env`. It fails the build when any of `NEXT_PUBLIC_SUPABASE_URL`,
`NEXT_PUBLIC_SUPABASE_ANON_KEY`, or `NEXT_PUBLIC_APP_URL` is missing, and names
the optional flags that are dark so a feature cannot go quietly off.

Output is **names only, never values**, so anyone debugging a build can paste it.
The error explains the inlining rule and gives the fix (`cp .env.local .`) rather
than only reporting absence — the failure mode is unintuitive enough that
"MISSING X" alone would send someone hunting in Cloudflare's dashboard.

## Verified

- With `.env.local`: `[public-config] OK — 3 required present (from .env.local)`
- Without it, in a directory containing no env files: exits **1**, listing all
  three and the remediation
- A local `next build` with the file present inlines "Continue with Google" into
  `app/auth/sign-in` and `app/auth/sign-up` chunks

## Acceptance criteria

- [x] A build missing required client config fails instead of shipping
- [x] The message names what is missing and how to fix it
- [x] Values are never printed
- [x] Optional flags that are off are reported, not silently ignored
- [x] Google sign-in restored to production

## Problem 1 — study chat was dead in production, and only in production

Founder: _"We need to address the on page chat. It doesnt work at all."_

Every chat request on a devotional page returned:

```
400  Devotional context is unavailable for this page.
     Open a devotional day before using study chat.
```

`buildDevotionalDocs()` (`src/lib/brain/rag-index.ts`) enumerates devotionals
with `fs.existsSync` / `fs.readdirSync` on `public/devotionals`. **Cloudflare
Workers has no filesystem**, so it returned `[]`, the canonical RAG index
carried no devotional docs, `findDevotionalDocs()` found nothing,
`hasDevotionalContext` was `false`, and the route rejected before ever reaching
a model.

Reference docs already had a Workers fallback (`loadReferenceIndex`).
Devotional docs never got one. The result: chat worked perfectly in `npm run
dev` — which has a filesystem — and failed 100% of the time in production. That
asymmetry is why it survived to production at all.

### Fix

`devotionalToRagDocs(slug, data)` is split out of `parseDevotionalFile()` so the
same doc-builder can run on a devotional that arrived over the network.
`findDevotionalDocs()` keeps the index fast-path and falls back to
`fetchTodayDevotional(slug)` — the Workers-safe loader the reader itself already
uses (tries `fs`, falls back to the published `/devotionals/<slug>.json`). No
new pattern, no new index, no build step.

Verified in the **Workers runtime** (`npm run preview`, workerd — no
filesystem), not in dev, because dev cannot reproduce the bug:

```
HTTP 200   hasDevotionalContext: true
citations: devotional:he-cannot-deny-himself-day-5:cover
           …:teaching:3  ("A treaty and a will…")
           …:pullquote:10 ("something had been cut in two")
```

The answer cited the devotional's own argument, not generic theology.

## Problem 2 — highlights were invisible on the cream page

Founder: _"the highlighting still doesnt work"_ — after the SA-038/SA-039 work
had already made the mark paint reliably.

It **was** painting. It could not be seen. Light-mode marks were translucent
(`rgba(246, 223, 128, 0.54)`) over the `#f0ece6` cream page, compositing to
`rgb(243, 229, 175)` against a `rgb(240, 236, 230)` paper — a few shades apart
in a single channel. A working feature that leaves no visible trace is
indistinguishable from a broken one.

### Fix

Highlighter colours are now opaque swatches in light mode, YouVersion-style,
with dark ink so the text stays legible on the colour. Dark mode lifts from
`0.34` to `0.62` alpha. Measured after: `rgb(247, 221, 110)` on
`rgb(240, 236, 230)`.

## Problem 3 — plain selection read as "the text went dark"

Founder: _"change the highlighted text in light mode to be white with the blue
highlight when not using the highlighter."_

`::selection` derived its background from the text colour
(`color-mix(--color-text-primary 70%, black 30%)`), which in light mode is a
near-black navy. Selecting text looked like the text had gone dark rather than
been selected. It is now white on brand cobalt (`--color-cobalt`, `#1f2a8d`) —
distinct from every highlighter colour, so "selected" and "highlighted" are
never confused.

### The selection fix had to move to its real source

The `::selection` rule added to `globals.css` was live in production and still
had no effect. `design-system/typography-craft.css` (imported at
`globals.css:2`) defines `::selection` **unlayered**, and unlayered CSS beats
anything inside `@layer utilities` regardless of source order — the Tailwind v4
layering trap already recorded in project memory.

Measured on production before the fix:

```
::selection  background: rgb(31, 42, 141)   cobalt
             color:      rgb(10, 19, 32)    deep navy  ← dark on dark
```

That rule also silently defeated the repo's own contract test, which asserts
"forces white text for browser copy/paste selection across engines". Both
design-system files now carry white-on-cobalt and agree with `globals.css`.

### Chat rendered its answers as raw markdown

`ChatMessage.tsx` printed `message.content` as plain text, so readers saw
`## Genesis 15` and `**covenant of grant**` as literal characters — the most
visible reason study chat did not read like a normal chat. Assistant messages
now render through `renderMarkdownSafe` (raw HTML disabled, the same renderer
Daily Bread uses); user messages stay plain text because they are input, not
markup. The blanket serif italic came off with it, since it now wrapped
headings and lists rather than prose.

Chat thread excerpts sliced the raw answer, so the sidebar preview opened with
`## Genesis 15 and the Covenant…`. `markdownToPlainText()` flattens markdown
for previews; 9 tests pin it.

### Verified in the browser, not inferred

Launcher → input → send → streamed reply, with the answer citing the day's own
treaty/will argument and rendering real headings and bold. Both Chromium and
WebKit (Safari's engine) drag-select, open the toolbar, and paint a highlight
at `rgb(247, 221, 110)` on production.

A WebKit run against `http://localhost` is worthless: WebKit force-upgrades
localhost to `https`, 37 requests fail on TLS, the page never hydrates, and
everything looks broken. Test WebKit against production HTTPS only.

## Platform contracts

### Desktop

Selection is white-on-cobalt; an applied highlight is an opaque swatch with
dark ink. Chat resolves devotional context server-side through the same loader
the page uses, so a study question cites the day being read.

### Mobile

Identical colour treatment at 375px — verified by drag-select on a touch
context that the toolbar appears, a colour applies, and the mark renders at
`rgb(247, 221, 110)`. No separate mobile styling was introduced.

## Verification

- Workers runtime (`npm run preview`): chat returns 200 with devotional
  citations; production returns 400 for the same request
- Light desktop / dark desktop / light mobile: selection → toolbar → mark
  painted, colours measured in the DOM
- `npm run type-check`, `npx eslint` clean

## Known gaps

- `public/reference-index-slim.json` is documented in CLAUDE.md as the index
  Workers uses instead of the 15 MB file. It does not exist; only
  `reference-index.json` (15 MB) is present. It loads, but the doc and the repo
  disagree.
- The chat **panel layout** is loose: opened at 1280px it overlaps the site
  masthead rather than sitting as a contained drawer, and the page shows
  through beside it. Function is correct end-to-end — launcher, input, send,
  streamed reply, rendered markdown, citations — but the framing needs a
  designer's eye, so it was left rather than guessed at.
- A pre-existing React hydration warning fires on the devotional route
  ("server rendered HTML didn't match the client"). It predates this work and
  is unrelated to chat, but it is real and worth its own pass.

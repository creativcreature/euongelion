# F-075: Billing Subscription State — Single Source of Truth

## Problem

The premium tier had a load-bearing read/write split: Stripe webhooks wrote
`public.users.subscription_tier`, but every entitlement read (billing/
entitlements, chat quota, chat usage, brain providers) checked Supabase Auth
`user_metadata`/`app_metadata` — which the webhook never wrote. A real paid
subscription would never activate. Customer↔user mapping was email-match only
(no `stripe_customer_id` stored), checkout passed no user identity to Stripe
(`client_reference_id` was a hashed IP), webhooks had no replay-safety store,
and one-time 2yr/3yr plans were created in `subscription` mode (they would
fail at Stripe) with no term-expiry tracking.

## User Expectation

- Paying activates premium immediately and durably; cancelling reflects
  honestly; renewal dates shown in Settings are real.
- No entitlement ever granted from a client redirect — webhooks only.

## 10/10 Definition

- `public.users` is the only subscription-state source (webhook-written, read
  via `src/lib/billing/subscription-state.ts`); zero metadata tier reads.
- Customer mapping precedence: stored `stripe_customer_id` →
  `metadata.user_id` → email (first-link fallback that persists the id).
- Webhook idempotency store (`stripe_webhook_events`), checked before
  dispatch, recorded after success (at-least-once, idempotent handlers).
- Checkout is authenticated, creates/reuses a Stripe Customer, passes
  `user_id` metadata, uses `payment` mode + `premium_expires_at` for one-time
  term plans.
- Nightly reconciliation against Stripe (Phase 1e deliverable).

  with the paywall/management features.

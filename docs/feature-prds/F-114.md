# F-114: Preview sits on a centred measure, and every entry carries its plate

## Metadata

- Feature ID: F-114
- Category: Reading surfaces
- Owner: founder
- Status: shipped (2026-08-16)
- Decision: SA-070
- Surfaces: `/series`

## Problem

> "the two columns should be centered on page. There are missing images in Rack
> and Feature toggles."

Two separate faults, reported together.

## 1. Preview was left-anchored, not centred

The rows stretched the full width of the browser. Because the plate column is
deliberately **fixed** (`clamp(200px, 24vw, 320px)` — see F-113, which is what
holds every row near 210px instead of 390px), all the slack landed in the copy
column. On a wide display that put the summary against the left edge with a
long empty gutter to its right.

The fix is a measure, not a stretch: `width: min(100%, 74rem)` with
`margin-inline: auto`. The pair now sits centred on the page, the summary keeps
a readable line length, and nothing about the row height changes.

## 2. Feature was genuinely missing five images

Not a loading problem — a markup problem. The brief rail rendered
**headline + byline only**, with no plate at all. Measured on the live site:

| View    | `/series/` links | `<img>` elements |
| ------- | ---------------- | ---------------- |
| Feature | 37               | **32**           |
| Rack    | 37               | 37               |
| Covers  | 37               | 37               |
| Preview | 37               | 37               |

Five series appeared in this view with no artwork whatsoever. Each brief now
carries a small square plate (72px, 56px under 640px) beside its text.

## 3. Rack's plates were lazy

Rack's markup was complete, but its plates were `loading="lazy"` in a rail. A
plate that has not scrolled into view has no pixels, which is indistinguishable
from a missing image to anyone looking at the page. They load `eager` now.

This is the **fourth** time lazy loading in a rail or transformed container has
been read as missing artwork (the rose window, Flow twice, now Rack). In a
dense rail of small plates, eager is the correct default.

## Contracts

### Desktop

- Preview rows sit on a centred measure — `min(100%, 74rem)`, `margin-inline:
auto` — with the fixed plate column on the left and the summary beside it.
- Feature's brief rail shows a 72px square plate for every entry.
- Rack plates load eagerly, so the rail is populated on arrival.

### Mobile

- Preview collapses to one column under 700px; the plate sits above the copy,
  which is the only readable arrangement at that width.
- Feature's brief plate steps down to 56px under 640px so the headline keeps a
  usable line length beside it.
- No horizontal overflow at 390px in any view.

## Acceptance criteria

- [x] Preview rows sit on a centred measure at every viewport

- [x] Rack plates are populated without requiring a scroll
- [x] Row height unchanged (~210–245px); no layout regression
- [x] Series-browser and layout-overflow tests pass

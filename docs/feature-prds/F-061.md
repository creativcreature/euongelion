## Follow-up: T-typo (2026-05-13) — literal `\uXXXX` escapes leaking into homepage JSX

Founder reported visible `·` and `—` strings on the live site
where `·` (interpunct), `—` (em-dash), `–` (en-dash), `→`, `À`, and
`§` were intended. Affected sections include the audit-shipped trust
strip (T6) and section-index card — content authored as part of this
PRD's T5/T6 batch.

Root cause: the strings sat as JSX text rather than inside JS string
literals, and TypeScript only decodes `\uXXXX` inside `'...'` /
`"..."` / template literals. Repo-wide audit confirmed the bug was
isolated to `src/app/page.tsx` (the audit-batch homepage rewrite);
all other `\uXXXX` occurrences across `src/` sit inside JS string
literals or regex char classes and parse correctly at runtime.

- `src/app/page.tsx`: 18 substitutions — 11 in user-visible JSX text
  (Bible-365 browse link, trust strip, section-index card, colophon
  strip, Soul Audit H2), 7 in `{/* ... */}` source comments cleaned
  for consistency.

Verified live (`localhost:3333`): all five affected user-visible
strings render with correct Unicode and a runtime DOM check confirms
no `\uXXXX` substring remains anywhere in `document.body.innerText`.

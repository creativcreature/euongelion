## Problem

The 30–60s composing wait was a generic progress surface: stages not
bound to real job transitions, escapable mid-composition, no designed
failure, arrival without acknowledgment of what the user named. The
founder resolved the wait as a HELD MOMENT ("press room meets Upper
Room") with a consent-cued arrival echo. Separately, sign-in lacked the
Google quiet-peer path (§5) and signup had no bot containment (§12.4).

## User Expectation

- The wait feels crafted and truthful: stages check only when the real
  work completes; failure names itself and offers a way forward; the
  arrival shows my edition heard _me_.
- Sign-in stays email-first with Google one tap below; no bot walls for
  humans (invisible challenge only).

## 10/10 Definition

- Stage checklist ratchets on real job signals only (poll `progress`/
  `currentDay`/route); duration expectation stated once; held moment
  owns the screen (tab bar hidden via `data-held-moment`, no dismiss)
  but never traps: bounded silent retries, frozen checklist + TRY
  AGAIN/Start over on failure.
- Desktop = press-room spread (production-schedule column + edition-
  press emblem at broadsheet scale, Upper-Room register); mobile =
  full-screen emblem + checklist (SA-024).
- Arrival echo: quote typed words only same-session (sessionStorage
  marker); otherwise abstract-but-specific (theme + anchor). Single
  BEGIN DAY 1 CTA. No confetti (SA-025).
- Google renders below email/Continue only when
  `NEXT_PUBLIC_GOOGLE_AUTH_ENABLED='true'`; Turnstile invisible widget +
  server siteverify only when both keys set (absent = byte-identical
  prior behavior; siteverify outage fails CLOSED with honest copy).

## Problem

Until now there was no user-controlled way to set the active devotional. `/api/soul-audit/current` resolved one from Soul Audit selections only, the homepage "TODAY'S DEVOTIONAL" was hardcoded to `bible-365-day-1`, and there was no surface that let the user save a devotional for later or restart a paused series. Authenticated users had no durable concept of "my reading."

## User Expectation

- On any devotional reader page I can tap **Save this Devotional** to add it to my personal library.
- On any devotional reader page I can tap **Start this Devotional** to set its parent series as my single active devotional.
- The active devotional renders **fully inline** on `/daily-bread` — not as a link card — with day-by-day navigation and pause controls.
- When I tap Start while another series is already active, a pastoral modal asks whether to **Start on Monday** (queue) or **Replace today** (immediate). The replaced series moves to my archive so I can restart it later.
- A new `/library` page surfaces my Saved, Paused, and Completed series with one-tap actions to Activate, Resume, or Restart from Day 1.
- Anonymous users see the buttons; tapping either opens a sign-in modal that captures my intent and replays it after I sign in via magic link.

## 10/10 Definition

- Save state and active-series state survive sign-out, sign-in, refresh, and cross-device sessions (cross-device via Supabase persistence).
- PK constraint on `active_series.user_id` enforces "one active at a time" at the DB level — no app-level drift possible.
- RLS prevents any user from reading or mutating another user's library.
- Pastoral switch modal is the only path to overwrite an active series; the displaced series is always restorable.
- `/daily-bread` renders the full devotional content inline using the same `ModuleRenderer` / panel pipeline as the dedicated reader — typographically identical reading experience.

## Device Contracts

### Desktop

- Two CTAs sit horizontally near the top of the reader (after the header, before module list).
- `/library` renders a responsive 16rem-min grid of saved + archived cards.
- `/daily-bread` shows the inline reader with a horizontal day-strip and a 2-column prev/next nav.

### Mobile

- CTAs stack vertically; PastoralSwitchModal occupies most of the viewport.
- Day-strip wraps; full-width prev/next.
- Sign-in modal is full-bleed.

## Scope

### In scope

- `active_series` / `scheduled_series_swap` / `archived_series` tables with RLS.
- API: `/api/devotionals/{active,saved,archive,archive/restart}` — auth-gated, structured 401 with `AUTH_REQUIRED`.
- Zustand store `devotionalLibraryStore` with optimistic updates and intent-replay event channel.
- `DevotionalActions`, `PastoralSwitchModal`, `SignInIntentModal`, `CuratedActiveView`, `ScheduledSwapBanner`, `/library` page.
- `LIBRARY` link in primary nav and account dropdown.

### Out of scope

- Wiring homepage `HomepageBento` "TODAY'S DEVOTIONAL" to the user's active slot (stays hardcoded to `bible-365-day-1`).
- Reading streaks, day-completion celebrations.
- Cross-device offline merge of actions taken while offline.
- Soul Audit deprecation — Soul Audit continues writing to the unified slot via `source='soul_audit'`.

## Risks and Rollback

- Risk: missing Supabase env in a dev/preview env could break `/daily-bread`. Mitigated: server-side resolution wrapped in `resolveUserActiveSeries()` try/catch that returns null and falls through to the existing Soul Audit path.
- Risk: rendering JSX inside try/catch was flagged by `react-hooks/error-boundaries`. Mitigated: extracted the data fetch into a helper that returns the row (or null) before any JSX.
- Rollback: revert the commit. The new tables can stay empty; Soul Audit + bookmark functionality is unchanged.

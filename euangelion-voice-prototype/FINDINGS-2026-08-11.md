# Devotional audio — findings, 2026-08-11

Investigation into why the Audio Edition "is robotic and doesn't work" for
listening while working. Every number below is measured on this machine, not
estimated. Reproduction commands are in §9.

---

## 1. The headline: two independent defects

The audio fails for two unrelated reasons, and the second one is not about
voice quality at all.

**Defect A — the voice.** The shipped Audio Edition is the browser's Web Speech
API (`src/lib/audio/tts-adapter.ts`, F-030). It is a screen reader. No amount of
voice-ranking fixes that; it is the wrong class of engine.

**Defect B — it skips about a third of every devotional.** Measured across 521
devotionals, the reader speaks a **median 70.7% of the distinct prose** in each
entry. 208 devotionals fall below 70%; 11 below 50%. This is a shipped verbatim
bug that exists independently of which voice reads it.

`moduleText()` in `src/lib/audio/segments.ts` reads a fixed field list. The
corpus carries prose in fields that list never names. Unread text, corpus-wide:

| Module type     | Words never spoken | Fields dropped                                                                                    |
| --------------- | -----------------: | ------------------------------------------------------------------------------------------------- |
| `profile`       |             69,122 | `lessonForUs`, `description`, `keyQuote`, `bio` — the whole "Voice Behind Today" module is silent |
| `insight`       |             65,719 | `historicalContext`, `fascinatingFact`                                                            |
| `vocab`         |             49,878 | `usageNote`, `rootMeaning`, `meaning`                                                             |
| `bridge`        |             36,435 | `newTestamentEcho`, `question`                                                                    |
| `story`         |             18,459 | `connectionToTheme`                                                                               |
| `scripture`     |              2,021 | `scriptureContext`, `fullPassage`                                                                 |
| `comprehension` |                321 | `question` — the answer is read without the question                                              |

Roughly **252,000 words** across the catalog are never read aloud.

There is a second, subtler defect in the same code path: `vocab` modules define a
word, but `word` / `transliteration` are not in the field list, so the reader
speaks a definition with no headword — _"safety, security, certainty — the
settled condition of a thing that is not going to give way"_ with no indication
that the word being defined is _asphaleia_.

## 2. Why the previous prototype stalled

`euangelion-voice-prototype/` (2026-07-22, never committed) built a local
voice-clone pipeline on Voicebox + qwen-TTS with a measured pacing spec. Two of
its foundational numbers turn out to be wrong:

**The calibration constant is wrong.** `NARRATION-PACING-SPEC.md` §1 records the
founder's "natural speaking rate" as **2.82 w/s**, derived from 5 hand-picked
interview clips. Re-measuring the full 24-minute source interview, isolated to
his voice by F0 fingerprint (72 clips, 641s), gives a pooled rate of
**3.57 w/s**. The 2.82 figure describes 5 unusually slow clips, not his speech.

**The QA numbers are wrong.** §8 reports take A3 landing at 2.87 w/s, "within 2%
of natural". Measuring the stitched file directly:

| Take               | Reported | Actually measured |
| ------------------ | -------: | ----------------: |
| takeA              |        — |          4.13 w/s |
| takeA2             |        — |          3.75 w/s |
| takeA3             | **2.87** |      **3.48 w/s** |
| takeB (chatterbox) |        — |          3.63 w/s |

v1 computed rate from API-reported chunk durations rather than from the audio it
wrote. The pipeline never actually hit its targets, which is consistent with the
takes sounding wrong.

## 3. What the local engine can and cannot do

Measured on qwen-TTS 1.7B / MLX / Apple Silicon, one scripture line, all
combinations:

| Lever                                  | Result                                                                                                                                                                       |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Seed (7, 11, 23, 42, 101)              | 4.09 – 5.05 w/s. Moves rate ~±0.4, no more.                                                                                                                                  |
| Register-specific reference profiles   | **No effect on pace.** Built two new profiles from rate-banded founder clips; reflective profile rendered 4.61–5.22 vs baseline 4.09–5.05 — overlapping, if anything faster. |
| `instruct` ("read slowly, reverently") | **Confirmed no-op.** Byte-identical duration to no-instruct.                                                                                                                 |
| Chunk length (10/20/30/45/60 words)    | Roughly flat, 3.0–3.6 w/s on prose. Not a pace lever.                                                                                                                        |

**Conclusion:** nothing in the generation stack reaches the 2.3–2.8 w/s
devotional band. Spec §9's claim that "reference-sample prosody dominates output
prosody" and that "sample selection IS the pacing tool" is false for this engine.

Two further limits worth recording:

- **Cloning is partial.** Output F0 measures 74.8–79.2 Hz against the founder's
  84.2 Hz. It is in the neighbourhood, not a match.
- **The reference material is conversational.** All 641s of usable founder audio
  is interview speech with natural filler. A clone built from it will carry
  conversational prosody regardless of pace correction.

## 4. Fixed in the live app

`src/lib/audio/segments.ts` now carries the corrected reading contract, so the
shipped Audio Edition benefits immediately regardless of which voice engine
ends up reading it:

- explicit ordered field list per module type, with mirrored variants
  (`content`/`body`) collapsed to one read
- a **catch-all sweep** — any substantial prose field the ordered list does not
  name is still read, so a field appearing in only a handful of modules can
  never go silent again (this is how `sabbath.content`, 295 words, was lost)
- dedupe so nothing is spoken twice (pull quotes repeat body prose)
- vocab headwords restored — "The Greek word asphaleia" before its definition
- Hebrew/Greek glyphs stripped; the parenthetical transliteration survives
- scripture references expanded to spoken English, including compound forms
  ("Job 1:1, 20-22; 2:10")
- navigation modules (video, cta, resource, images) no longer read

Measured over all 521 devotionals:

|                             |                   |
| --------------------------- | ----------------: |
| words spoken, before        |           648,094 |
| words spoken, after         |           888,899 |
| gain                        |        **+37.2%** |
| median per-devotional ratio |         **1.37×** |
| devotionals that regressed  | **0** (min 1.03×) |

Verification: `npm run type-check` clean; full suite **139 files / 1816 tests**
passing; 13 new tests in `__tests__/audio-segments-coverage.test.ts` pinning the
contract.

## 5. What was built for the render pipeline

Three new modules in `spec/`, all stdlib-only:

**`narration_extract.py`** — the corrected reading contract. Explicit ordered
field list per module type; mirrored fields (`teaching.content` ==
`teaching.body`, identical in 1,410 of 1,422 cases) deduped rather than read
twice; Hebrew/Greek glyphs stripped with transliteration retained; vocab
headwords restored ("The Greek word asphaleia" before its definition); scripture
references expanded to spoken English ("1 Thessalonians 5:2-3" → "First
Thessalonians, chapter five, verses two to three").

Result: **1.37× more words spoken** (median), **+38.3%** corpus-wide.

**`timestretch.py`** — WSOLA pitch-preserving time-stretch, using
`audioop.findfit` for the similarity search. Since pace cannot be reached in
generation, it is corrected in post. Factors stay ≤1.45, which is transparent on
speech. Costs ~1.5s CPU per 19s of audio.

**`render_v2.py`** — the pipeline. Chunks abbreviation-safely ("C. S. Lewis" no
longer splits), renders with seed retry behind a phonetic clarity gate,
stretches each chunk to its register target, stitches with the pause grammar,
and reports QA measured on the written audio rather than on API metadata.

Chunk ordering matters and v1 had it wrong: it merged short fragments _before_
hard-splitting over-long sentences, so split tails were never merged. That sent
`"having one."` (2 words) and `"until it repose in Thee.\""` (5 words) to the
voice as standalone utterances — an audible stumble mid-paragraph. v2 merges
last, and refuses a cut that would strand a tail under 8 words. Corpus-wide,
sub-5-word chunks are now 0.71%, and all of them are complete segments
(titles, references, short definitions) rather than fragments.

The clarity gate needed its own fix: comparing ASR output to source by spelling
scored correct readings as broken. `wilfully`→`willfully` is a British/American
spelling variant; `prophets`→`profits` a homophone; and Whisper writes "First
Thessalonians, chapter five" back as "1st Thessalonians chapter 5", scoring a
perfect reading at 0.50. The gate now compares Soundex keys and normalizes
numbers and ordinals on both sides.

## 7. The method that actually works: a preset narrator, not a clone

Founder call, mid-session: the clone approach is a terrible method — do
something different. Correct. Cloning conversational interview audio and then
slowing it in post was fighting the material.

The replacement is **Kokoro-82M**, which ships purpose-built narration voices.
Nothing is cloned, so there is no reference prosody to fight, no seed hunting,
and no time-stretch. Measured on the same devotional text, nine English male
voices, pace as **words ÷ total duration** (what the ear hears — the earlier
speech-only metric flattered the clone by excluding its missing pauses):

| Voice          |        Pace | Natural pauses |                            Verbatim |
| -------------- | ----------: | -------------: | ----------------------------------: |
| **am_michael** | **164 wpm** |             19 |                                100% |
| bm_lewis       |     168 wpm |             23 | 100% (**disqualified — see below**) |
| bm_george      |     170 wpm |             22 |                                100% |
| am_adam        |     188 wpm |             16 |                                100% |
| am_onyx        |     202 wpm |             14 |                                100% |
| am_eric        |     217 wpm |             14 |                                100% |

Professional audiobook narration is 150–170 wpm. The top three land inside the
band with no correction applied. The clone stack, for comparison, could not get
below ~205 wpm without stretching.

Two further advantages showed up in testing:

- **Whole segments render at once.** Kokoro took a 352-word segment in 12s at
  164 wpm with 44 natural pauses and 99.4% verbatim. Prosody arcs across the
  paragraph instead of resetting every 40 words, which is what made the chunked
  clone takes sound stitched.
- **It is ~20× faster.** 3.8 minutes to render the full devotional versus ~2
  hours on the clone path.

`spec/render_kokoro.py` is the resulting pipeline: extract → render whole
segments → stitch with the pause grammar → QA. No chunking, no stretching, no
seed hunting.

### bm_lewis disqualified on evidence

Full renders of all three finalists put `bm_lewis` at mean clarity 0.983 against
0.997 / 0.996 — and the gap was a real defect, not an artifact. Given
"First Thessalonians, **chapter five**, verses two to three" it says
"1 Thessalonians 5, verses 2-3", dropping the word _chapter_. Same omission on
"Hosea, **chapter ten**". Both other voices say it. Handed digits instead
("chapter 10") it is fine, so the fault is specifically spelled-out chapter
numbers — which is exactly what §4's reference expansion produces. It also reads
"Job" as "Jab".

This is the clarity gate doing the job it was built for: catching a defect that
a pace-and-pauses comparison would have missed entirely.

### Full-catalog feasibility

At the measured throughput of 921 words/min wall clock:

|                              |                                    |
| ---------------------------- | ---------------------------------: |
| devotionals                  |                                521 |
| words to narrate             |                            888,585 |
| render time, single-threaded | **16.1 hours** (one overnight run) |
| audio produced               |                         91.4 hours |
| storage @64 kbps mono        |           2.5 GB (1.3 GB @32 kbps) |

That is the whole catalog pre-rendered, locally, at zero marginal cost — and
pre-rendered files are what make real background playback, lock-screen controls
and offline listening possible at all.

## 8. Verdict

The pipeline produces **verbatim, correctly-paced** narration at 162 wpm with
mean clarity 0.990, rendering a full devotional in under four minutes at zero
cost. Both objectively measurable requirements — read every word, read it at
narration pace — now pass.

What changed the outcome was abandoning the premise. The founder's voice was
never the requirement; a good listening experience was. A purpose-built
narrator clears that bar today, where a clone built from ten minutes of
conversational interview audio could not have, at any amount of iteration.

**Recommended sequence:**

1. Founder listens to `takeD` (am_michael) and `takeE` (bm_george) and picks a
   voice — the one judgement that cannot be automated here.
2. Pre-render the catalog overnight (16 hours, free) to R2.
3. Build the real player on those files: `<audio>` element, persistent
   mini-player, Media Session, auto-advance, offline. This is the half that
   makes "listen while I work" actually work, and it is impossible while the
   reader is `speechSynthesis`.

A founder-voice ElevenLabs clone stays available later as a premium upgrade for
flagship series. It is no longer on the critical path.

## 9. Reproducing

```bash
# extraction, any devotional (complete + verbatim + register-tagged)
python3 spec/narration_extract.py public/devotionals/<slug>.json

# render (needs Voicebox running on 127.0.0.1:17493 with the kokoro model)
python3 spec/render_kokoro.py public/devotionals/<slug>.json out.wav \
        --voice am_michael [--limit N]

# a listenable excerpt for judging a voice
python3 spec/make_sample.py out.wav SAMPLE.wav 120
```

Voicebox profiles left on the machine: `Kokoro — am_michael`,
`Kokoro — bm_george`, `Kokoro — bm_lewis` (the three candidates), plus the
original `James — Founder Voice`, which was never modified. The mined
register-clone profiles built during the dead-end investigation have been
deleted, along with every generation created during this session.

`spec/render_v2.py` and `spec/timestretch.py` are retained: v2 still holds the
phonetic clarity gate that `render_kokoro.py` imports, and the time-stretch is
the tuning knob if a chosen voice needs its pace nudged (factors under ~1.15 are
inaudible).

### Tunable knobs

- **Voice** — `--voice`; any Kokoro preset. `am_michael` 164 wpm, `bm_lewis`
  168, `bm_george` 170.
- **Pause grammar** — `PAUSE_AFTER` in `render_kokoro.py`. Current values came
  from the founder's own measured speech (max 0.70s), a constraint that no
  longer applies now the narrator is not him; longer beats before scripture and
  prayer are worth trying.
- **Citations** — whether source notes like "The Problem of Pain (1940),
  chapter eight" should be spoken at all is an editorial call, not a technical
  one. They are currently read.
